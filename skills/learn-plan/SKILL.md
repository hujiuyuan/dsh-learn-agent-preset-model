# 出计划 · 细化当前节 · 调整计划

核心规则：**越远越粗，只细化眼前这一节。** 不一次铺开半年，不排日历。

## 1. 出路线（第一次）

先修问答没做完，脚本会拒绝出路线；按 `learn prereq` 的「下一步」做完再来。

1. 从终点考核往回拆：「要做到这个，必须先会什么」，一直拆到摸底为 `mastered` 的能力为止，得到依赖关系。
2. 按依赖排成小节。一节只学一个点，大小以「用户一次可用时间内能学完并检验完」为准。达标标准里有两三件互相独立的本事（比如 axis、广播、矩阵乘法），就是两三节，不要并成一节。
3. 超过 10 节就先分阶段，只展开当前阶段的小节，其余阶段只写一句话。
4. 路线层每节只写 `id`、`title`、一句话 `summary`、`requires`。**不提前定教法和达标标准**，学到时再定。
5. 按先修决定（`learn prereq` 可查）排：
   - 选了**先补**的技能：加 1-2 节先修节 `{"kind":"prereq","prereqSkill":"<技能>"}`，只讲本课要用的部分。第一次出路线时编号排在用到它的节前面；课中再加的用新 id，脚本按 `uses` 自动接上依赖。
   - 用到某项先修（任何决定）的节，在 `uses` 里写上它，一项写一个技能名，照抄先修清单里的名字。脚本会自动把先修节加进这些节的 `requires`，学到「边学边补」的节时会提示先补。

```
learn set-plan --json '[{"id":1,"kind":"prereq","prereqSkill":"HTTP 基础","title":"HTTP 请求与状态码","requires":[]},{"id":2,"title":"第一个接口","summary":"…","requires":[],"uses":["HTTP 基础"]}]'
```

「先修」指本课以外的技能（Java、HTTP 基础）；「前置节」指本课路线里的依赖节（`requires`）。两个词不要混用。

6. 给用户看路线，**不超过 15 行**：终点考核、各节标题（每节一句话）、大约要学几次、第一节怎么学。用户可以改顺序、删节、指定教法。**给出路线后停下来，等用户回复**；用户确认后才 `learn start` 第一节。

## 2. 开始一节前细化（每节都做）

依据这门课到目前为止的实际表现（`learn status` 里的检验备注、本节记过的错）来定。

status 写着「已暂停，做完 k/m 步」的节已经细化过：直接 `learn start <节>`，不带任何参数，接着做，不要重新细化。

**先问接触过没有**：摸底里没有这一节的内容，就先用一个问题问用户以前见过、用过没有（选项：完全没接触过 / 见过但没用过 / 用过）。不要用内容题来探，没见过的东西只能瞎猜。

**选教法**，按顺序检查，第一条命中的就用：

| # | 情况 | 教法 |
|---|---|---|
| 1 | 用户点名要某种教法 | 用户指定的 |
| 2 | 用户从没接触过这节的内容（摸底为 `none` 且依据是没见过、看不懂或不确定，或刚才答「完全没接触过」），动手类和概念都算 | `worked-example` 示范例题 |
| 3 | 摸底为 `partial`，或之前在相关点上出过错 | `diagnose` 诊断纠偏 |
| 4 | 动手类（写代码、操作工具、做题） | `coach` 练习批改 |
| 5 | 核心概念或原理，用户接触过，且后面很多节依赖它 | `first-principles` 第一性原理 |
| 6 | 其他 | status 有「默认教法建议」就用它（只会是练习批改或示范例题），没有用 `coach` 练习批改 |

上一节哪种教法好用，不能盖过第 2 行：从没接触过的东西，先讲再问。status「上次」里你自己总结的「用户适合某种教法」不算用户点名。费曼不在表里：每节的检验环节固定用费曼。

**写达标标准**：可检验，例如「给 3 段代码都能说对输出顺序并讲出原因」。

**拆步骤**：每步 10-15 分钟，最后一步固定是检验。从没接触过的节，第一步是讲解和示范（如 `"示范：np.zeros 建数组（完整代码和输出）"`），不是探测题；每个新知识点（新函数、新规则）都要有自己的示范步骤（一步只放一个），「你做」的步骤只练已经示范过的东西。

```
learn start 3 --method diagnose --reason "摸底第2题半懂" --criteria "3 段代码都说对输出顺序并讲出原因" --check "费曼 + 1 道新题" --steps '["探测：1 道预测输出题","纠偏","变体题 2 道","费曼检验"]'
```

把这几步同步写进 todo 工具，然后加载对应的教法 skill（`teach-<教法>`）开始。

## 3. 调整计划

出现以下情况时调整，改完用一两句话告诉用户改了什么、为什么：

| 情况 | 做法 |
|---|---|
| 检验没过，但只卡在本节的某一块（其余做对了）；这一节换过一次教法还卡；用户说这节太大了 | `learn split <节> --keep "<做对的部分>" --criteria "<只考做对的部分>" --json '[{"title":"<卡住的那块>","summary":"<卡在哪>"}]' --steps '[…]'`：拆出去的节接在后面学，学到时再细化。`--steps` 是本节剩下的步骤，只讲、只考留下的部分；留下的已经学完就只写一步检验。拆完脚本会列出本节的错题：属于拆出去那块的 `learn mistake <id> --to <新节>` 挪过去 |
| 讲课时用户说「换种方式 / 换个学法 / 换个讲法」，或说乱、烦、算了（这样学没学懂，耐心也快没了；话里说了今天到这、不学了、歇会儿的，按人设「累」先问要不要停） | 不问换什么、不给选项让用户挑：`learn switch <节> worked-example "用户说换" --user --steps '["示范：<卡住的那块>（完整代码和输出）","补全题","独立题","费曼检验"]'`（做完的步骤保留；已经是示范例题也这样重拆，退回示范这一档），加载 `teach-worked-example`，按它的「用户说换」只讲卡住的那块、这一轮不出题。正在检验就先 `learn done <节> --fail --stopped --note "…"`（见 `teach-feynman`）再换。本节剩下的都按示范例题讲完，不换回去。`--user` 表示是用户要求的，不算进「一节最多换一次」 |
| 用户点名要某种教法（「换成练习吧」） | `learn switch <节> <点名的教法> "用户点名" --user --steps '[…]'`，只按点名的那种拆步骤，不把别的混进来 |
| 退回前置节后仍然卡住 | 在卡住的节前插一个更小的过渡节 |
| 连续 3 节开场探测都直接过 | 合并后面的节，或跳到更深的节 |
| 用户说目标变了 | 回到 `learn-intake` 重定终点，保留已掌握的节 |
| 期限快到、进度落后 | 列出可以砍掉的非关键节，让用户选，写清砍掉的后果 |
| 学完一个阶段 | 展开下一阶段的小节；这一阶段新用到的先修（0-2 项）先 `learn prereq set --append --json '[…]'`，按「下一步」问完再排（每批最多 4 道验证题） |
| 课中发现缺本课以外的技能 X（用户问「X 是什么」，或卡在 X 上） | `learn prereq gap "X" --reason "…" --lesson <节>`，先用用户会的技能讲 X 本节要用的最小部分（不超过 3 轮），再按输出只问一件事：怎么补（不再问会不会、不出验证题） |

调整的做法：

1. 先运行 `learn plan`，拿到当前完整路线（含每节的 id 和最大 id）。
2. 在它上面改，再用完整的新路线 `learn set-plan`。
3. **已有的节不改号**；新加的节用没用过的 id（比最大 id 大），顺序靠 `requires` 表达，不靠编号。脚本发现有记录的节被改了标题或类型会拒绝。
4. 某节省略 `uses` 时沿用原来的；要清空就写 `"uses":[]`。
5. 新路线漏掉了有学习记录的节，脚本会拒绝；确认要删才加 `--force yes`。
