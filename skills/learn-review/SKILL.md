# 续学 · 复习 · 收尾 · 结业

## 1. 续学开场

`learn status` 的输出就是接续信息。status 写着「还没立目标」或「还没出计划」：照它的「下一步」做（通常是回到 `learn-intake` 或 `learn-plan`），不走下面的开场。

有计划时，第一句回复用两三句话说清：

- 上次学到哪、学得怎样（引用 status 里的「上次」那一行）
- 有没有未解决的疑问、到期复习
- 今天的安排：先疑问和复习，再继续当前节

接着加载 status 里写明的那个教法 skill（不要换成别的），按它继续当前步骤。开场这条回复的最后一行同样是位置条（抄 `learn now` 的输出）。

示例：「上次你学到第 3 节，纠偏做到一半，对『阻塞』还有点模糊，还留了一个问题：time.sleep 放在 async 函数里会怎样。今天先花 5 分钟把这个问题和 1 道复习题过掉，再接着学，好吗？」

特殊情况：
- status 开头有「同步：」行：原样告诉用户一句。开头是 **⚠ 同步冲突**：先处理它，按第 7 节做，选完再开场。
- status 标了 **⚠ 没有正常收尾**：先问用户最后那一步要重做还是接着做。
- status 有「⚠ 已经 N 天没学」（14 天及以上才会出现）：对已掌握的节各出 1 道题快速摸底，测不过的用 `learn review --lesson <节号> --reason "…"` 标为需复习。
- 有多门课：status 只显示最近那门；用户想学别的，`learn use <课程名>`。
- status 有「等待先修」：用户之前选了先单独学那门技能。问用户那门学完没有，按 `learn prereq` 输出的出口做：
  - 还没开始：`learn init <短名> --title "…" --for <本课>:<技能>` 新开一门，那门结业时自动解除等待；
  - 已经开了：`learn use <那门课>`；
  - 在别处学会了：出 1 道验证题，`learn profile verify` 记下，再 `learn prereq decide "<技能>" known`；
  - 不想等了：`learn prereq decide "<技能>" inline`，改成边学边补。
- status 有「先修还有 N 项没定」：先按它的下一步问完。

## 2. 先处理未解决的疑问

逐个回答 status 里的疑问。用户确认懂了，`learn answer <qid> "<一句话结论>"`。疑问其实是误解，再记一条错题。

## 3. 错题复习

`learn due` 列出到期的错题（一次最多 5 条）。只复习它列出的，没到期的不要提前考（脚本会拒绝 `--pass`）。每条：

1. 出一道**新**题考同一个点，不要复述原题。标了「来自 X 的习惯」的，出一道按 X 的习惯会做错的预测题。
2. 答对：`learn review <mid> --pass`。答错：简短纠正，`learn review <mid> --fail`。

教学中用户又犯了一条已有的错（包括已经复习过关的）：`learn review <mid> --fail`，不要再记一条新错题。间隔由脚本算，不要自己算日期。

## 4. 收尾

用户说「今天到这」「下次再学」，或者快到用户设定的单次时长时：

1. 不再开始新步骤。
2. 运行：`learn pause --summary "<这次学了什么、表现如何、哪里还模糊>" --next "<下次从哪开始、先做什么>"`。summary 只写发生了什么，不写「以后默认用某种教法」这类结论。
3. 告诉用户下次从哪继续，一两句话。输出里的「同步：」行原样告诉用户；写着没推上去的，提醒用户换电脑前先让这台联网。

**用户直接离开不会触发收尾**，所以平时每完成一步都要 `learn step`，不能攒到最后。

## 5. 每日复习提醒

出完计划后，如果当前工具里有 `schedule_create`：问用户每天几点学，然后建一条每日提醒：

```json
{"title":"<课程名> 每日学习","prompt":"运行 learn status 和 learn due：有到期复习就先复习，没有就继续当前节。","daily":{"time":"20:00:00","time_zone":"Asia/Shanghai"}}
```

时区用用户所在时区。没有 `schedule_create`：只提示一次「在插件管理里打开『自动化任务』，可以每天定时提醒复习」，之后不再提。

## 6. 结业考核

status 显示全部小节完成时：

1. 出终点考核（目标里的 exam）。考核内容必须是新的，不复用教学和检验中的题。
2. 通过：`learn finish --pass --note "<考核结果和证据>"`，给一份总结：学会了什么、曾经错过哪些点、建议的下一个目标。有每日提醒就用 `schedule_delete` 删掉。输出里的「画像：」行原样告诉用户；输出提到有课程在等这门课，告诉用户可以回去接着学。
3. 没通过：`learn finish --fail --note "…"`，把没过的部分对应的节标为需复习，回到小节循环。

## 7. 多台电脑同步

进度和画像可以放进用户自己的 GitHub 私有仓库，在公司、家里都能接着学。连上以后脚本自己拉和推，你不用管。

- 用户想连：请用户在 GitHub 上建一个私有仓库，把地址给你（如 `git@github.com:<用户名>/<仓库名>.git`），并确认这台电脑的 git 能登录 GitHub。然后运行 `learn sync --remote <地址>`，结果原样告诉用户。另一台电脑装好学习教练后做同样的事。地址里不能带密码或 token。
- 用户问同步了没有：运行 `learn sync`，原样转告。
- **⚠ 同步冲突**：两台电脑各自记了同一门课的新记录，合不到一起（输出里点名是哪门课；其他课程和画像照常合并）。把两边各多出的记录告诉用户，说清两个选项的后果：
  - `learn sync --keep remote`：这门课用仓库里的，这台多出的记录存进备份分支，不会丢；
  - `learn sync --keep local`：这门课用这台的，仓库里多出的记录存进备份分支，不会丢。
  用户选了再运行。输出说「冲突的课程变了」：什么都没改，把新名单告诉用户重新问。不要自己选，也不要用 git 命令去改学习目录。
