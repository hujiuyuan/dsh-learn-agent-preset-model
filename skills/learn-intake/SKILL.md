# 立目标 · 先修 · 摸底

目的：把「我想学 X」变成一个能检验的终点，弄清用户已经会什么、缺什么，再找出起点。全程一次只问一个问题；只有第 3 步问「会不会」、问怎么补时，几项放进同一次提问。

## 1. 建档

`learn status` 显示没有这门课时：起一个课程短名（小写字母、数字、连字符，如 `python-async`），运行
`learn init <短名> --title "<中文名>"`。课程已经有了（status 写着「还没立目标」或「还没出计划」）就不再 init，从 status「下一步」指的那一步接着做。

## 2. 立目标

要弄清 4 件事。用户已经说了的不再问，一轮最多问两件，能用 ask_user_question 给选项就给选项：

| 问什么 | 用途 |
|---|---|
| 学会了能干什么 | 决定终点考核 |
| 用在哪（工作 / 考试 / 兴趣） | 决定例子和练习取材 |
| 什么时候要会 | 决定节奏 |
| 每次能学多久 | 决定一节多大 |

把答案写成**终点考核**：「做到 X 就算学会」，必须能检验。

- ✗「掌握 Python 异步」
- ✓「能写一个并发抓 20 个网页的脚本，并解释为什么比串行快」

目标太大（「学会机器学习」）：给 2-3 个更小的终点让用户选，每个写清「选这个，学完能做到什么、大概要学几次」。

定下来马上记录（`profileSkill` 是结业后记进画像的技能名，范围和终点考核一致，如「Python 并发抓取」，不要写成「Python」）：

```
learn set-goal --json '{"summary":"一句话目标","exam":"终点考核","profileSkill":"…","deadline":"YYYY-MM-DD 或省略","minutesPerSession":45}'
```

## 3. 已会的技能和先修（出计划的第一步）

1. 运行 `learn cues`，看当前目录的项目用了哪些技术。只当提问线索：项目用到不等于用户会。
2. 列一份清单，三类：
   - `core` 必需（最多 3 项）：本课以外、不会就学不下去的技能。例：学 Spring Boot 要 Java。
   - `general` 有帮助（最多 2 项）：不会只是学得慢一点。
   - `related` 可类比（最多 2 项）：用户可能会、能拿来打比方的技能，优先从 `learn cues` 的线索里挑。
   每项写 `reason`：本课哪部分用它做什么（60 字内）。写不出 reason 的不列。一项只写一个技能，名字取技术或主题这一层（Java、SQL、HTTP 基础），不写「Java 泛型」，也不写「Java 和 SQL」。从 `learn cues` 挑的，名字照抄它输出的写法。
3. 运行：
   ```
   learn prereq set --json '[{"name":"Java","role":"core","reason":"写控制器和实体类"},{"name":"Vue","role":"related","reason":"组件化思路可类比","cue":"package.json"}]'
   ```
   这门课用不到别的技能：`learn prereq set --none "<理由>"`。
4. **照着脚本输出的「下一步」做**：
   - 画像里已有可靠记录的，脚本会直接定，并告诉你哪些不再问；用一句话告诉用户依据。
   - 问「会不会」：脚本列出的几项放进**同一次** ask_user_question，每项一题。题面问具体任务（「你能不查资料写一个带参数的 GET 接口吗？」），不问笼统水平。是看了项目文件才问的，题面说出文件名。选项固定四个：A 能独立做 / B 会一点，要查资料 / C 没接触过 / D 不确定。答完每项各运行一次 `learn prereq answer`，答过的不再问。
   - 出验证题：**一次只出一题**，ask_user_question 里只放这一题，`learn prereq quiz` 记下后再出下一题。预测输出、找错、解释为什么，不问定义。选项规则同摸底第 5 条。只有必需和可类比的项会出验证题；有帮助的项用户选 A / B 就算够用，不验证。
   - 每批最多 4 道验证题（问会不会、问怎么补都不算）。名额按「必需第 1 项 → 可类比第 1 项 → 其余必需 → 其余可类比」分；分不到的必需项直接进「问怎么补」（推荐边学边补），可类比项不拿来打比方，脚本会标「名额用完没验证」，要你告诉用户的照说。用户坚持说会：出 1 题 `learn profile verify` 记下，再 `decide "<技能>" known`。
   - 问怎么补：每项先说本课用它做什么，再给四个选项，每个都写后果，标出脚本给的推荐项：
     - ① 先补：正课前加 1-2 节先修节，只讲本课要用的部分，多学 1-2 次
     - ② 边学边补：学到要用它的那节时先花 5-10 分钟补，那一节会长一些
     - ③ 先单独学一门：这门课先放着，新开一门课学它，学完回来
     - ④ 跳过：直接学，要用它的那节可能卡住，卡住时再回头补
     用户不选或说「你定」就用推荐项，说一句用了哪个。
     用户选 ③：脚本会给出新开那门课的命令（`learn init … --for <本课>:<技能>`），照它做；那门结业时这门课自动解除等待。
5. 每次命令输出的「画像：」行原样告诉用户。自评和验证结果对不上时只说一句「这题暴露了 X，按会一点安排」，不说「你高估了」。
6. `--detail` 只写题目要点和结果，不写「精通」「专家」「完全掌握」「熟练掌握」「完全理解」「完美」，脚本会拒绝；用户原话放 `--quote`。

## 4. 摸底

只测**本课路线上**的能力。本课以外的技能归先修，第 3 步问过的不再问。

1. 从终点倒推 4-6 个关键能力，从浅到深排好。
2. 用户自述了基础（「我会 X」）：先记下，仍然用 1 道题快速验证。
3. 每个能力出 **1 道**题，从中间难度开始：答对就往深跳，答错就往浅退，一般 3-5 题找到起点。先修里已验证会的相关技能，可以从深一档开始，但每项能力仍至少 1 题。
4. 题目要暴露理解，不考记忆：让用户预测输出、解释为什么、找错误。不问「X 的定义是什么」。
5. 用选择题时：**有且只有一个选项是对的**，出完先自己核对一遍；**选项和选项说明都不能暗示哪个是对的**（不写「答对就跳过」「说明你已经懂了」这类话），每个选项说明只写选项本身的意思，或者干脆不写说明。最后一个选项固定是「不确定 / 说不清」。
6. 选择题选对了还要追问一句「为什么」：能说出原因才算 `mastered`，只选对算 `partial`。
7. 用户答「不知道」是有效结果，记下即可，不追问。

每个能力判为三档：

| 档位 | 依据 |
|---|---|
| `mastered` 已掌握 | 答对，且解释说得通 |
| `partial` 半懂 | 答对但说不出为什么，或答错但思路接近 |
| `none` 没学过 | 不知道 / 完全错 |

自述和测试对不上时以测试为准，用一句话告诉用户哪道题暴露了什么。

## 5. 记录

```
learn baseline --json '[{"ability":"事件循环","level":"partial","evidence":"第2题答对但说不出原因"}]'
```

JSON 里有引号或较长时，先写到临时文件再用 `--file <路径>`，或用 `--json -` 从标准输入传。

写入成功后，用 3 行以内告诉用户：终点考核是什么、先修怎么处理、起点在哪。然后加载 `learn-plan` 出计划。

## 重定目标（已经有路线的课）

1. 照第 2 步问清新目标，再 `learn set-goal`。
2. 新目标新用到的本课以外的技能：`learn prereq set --append --json '[…]'`，只列新增的，按「下一步」问完。
3. 新目标新增的能力补摸底：`learn baseline` 只传新增的能力，脚本按能力合并，不会冲掉原来的结果。
4. 加载 `learn-plan`，按「调整计划」的做法改路线：已掌握的节保留，已有的节不改号。
