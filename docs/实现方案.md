# 学习教练预设 · 实现方案

> 版本：v0.4 · 2026-10-15（v0.2 已在 DSH 0.2.0-rc.2 上实测，结果见 §11；v0.3 新增学习者画像和先修问答；v0.4 按实测改了先修问答的名额规则，新增多台电脑同步，见 §3.4、§11.3）
> 配套：[方法论.md](方法论.md)（讲「怎么教」），本文讲「怎么落地」

---

## 0. 约束

1. **只用 DSH 自带的东西。** 预设只挂 `@deepseek-ai/*` 官方包，不依赖任何第三方插件。
2. **能力缺了要降级，不能报错。** DSH 的「自动化任务」默认关闭，没开时学习照样能进行，只是没有定时提醒。
3. **跨平台。** macOS / Linux 走 bash，Windows 走 PowerShell，脚本不能依赖 shell 语法。

## 1. 总体思路

- **进度只存在文件里，不靠模型记。** 对话会断、会被压缩，文件不会。
- **模型只在固定时机读写。** 什么时候读、什么时候写，都写死在人设和 skill 里。
- **精确计算交给脚本。** 复习日期、到期判断、格式校验、生成接续信息都由脚本做，模型只负责调用。

## 2. 用到的 DSH 能力

DSH 桌面版的预设是**白名单**：只有写进预设插件列表的能力才会挂给模型。所以只需列出要用的，其余天然不挂。

### 2.1 挂哪些

| 能力 | 官方包 | 用来做什么 |
|---|---|---|
| 人设 | `dsh-persona`（`complete: false`，保留运行时上下文：时间、工作目录） | 总控规则 |
| 工作区指令自动加载 | `dsh-agent-instructions` | 加载全局 `~/.dsh/AGENTS.md`（§5.5）和项目自己的指令 |
| 读写文件 | `dsh-tool-fs`、`dsh-tool-fs-search` | 读写学习档案、批改作业 |
| 命令行 | `dsh-tool-bash` / `dsh-tool-pwsh`（按平台二选一） | 跑 `learn` 脚本、跑练习代码 |
| skill | `dsh-skill-filesystem`、`dsh-tool-skill` | 按需加载流程和教法，目录配置见 §2.4 |
| 问用户 | `dsh-tool-ask-user` | 立目标、确认计划时给选项 |
| 待办 | `dsh-tool-todo` | 跟踪一节课里的 5 步 |
| 压缩 | `dsh-compaction-basic`、`dsh-command-compact`、`dsh-compaction-tool-result-pruner` | 长对话不爆上下文 |
| 联网 | `dsh-tool-web` | 备课、核对事实，防止讲错 |

### 2.2 不挂哪些

| 能力 | 原因 |
|---|---|
| 计划模式 `dsh-plan-mode` | 写代码前出方案用的；还会禁止写文件，进度记不下来 |
| 子代理、workflow、ralph | 一对一教学不需要派活，挂上只占提示词 |
| 目标模式 `dsh-goal`、`dsh-tool-goal` | 让 agent 自己连续跑到完成，和「每步等用户回答」的节奏冲突 |
| 后台任务 `dsh-tool-jobs` | 练习代码几秒就跑完，不需要后台进程 |
| 展示交付物 `dsh-tool-present` | 学习没有要交付的文件 |
| 插件管理 `dsh-plugin-manager/tools` | 学习过程中不该改 DSH 配置 |
| 持久终端 `dsh-terminal` 一组 | 普通 bash 够用 |
| Office skill `dsh-skill-office` | 默认不挂；学 Excel、PPT 这类技能时再加 |

### 2.3 不归预设管、会自己混进来的

| 来源 | 处理 |
|---|---|
| 「自动化任务」（`dsh-schedule`，官方可选 bundle，默认关闭） | 打开后对所有预设生效，带来 `schedule_*` 工具和时钟读数。正好要用，保留；没开时退化成开场提醒，见 §6 |
| 用户配置的 MCP 服务器 | 预设挡不住，人设里写一句「只用教学相关的工具」 |
| 用户全局和项目里的 skill | 通过 §2.4 的目录配置挡掉 |

### 2.4 skill 目录

skill 加载默认会扫 `~/.dsh/skills`、`~/.agents/skills` 和工作区里的 `.dsh/skills`，会把用户其他无关的 skill 混进学习预设。所以关掉默认目录，只扫三个目录：

| 目录 | 放什么 | 对谁生效 |
|---|---|---|
| 预设包自带的 `skills/` | 9 个教练 skill | 所有课程 |
| `~/.dsh/learn-skills/` | 用户加的学习用 skill | 所有课程 |
| `~/.dsh/learning/<课程>/skills/` | 用户加的、只给这门课用的 skill | 这门课 |

```yaml
- id: skill-filesystem
  name: '@deepseek-ai/dsh-skill-filesystem'
  config:
    includeDefaultRoots: false
    # 本包自带的 skill：从 patch 所在位置解析出包目录（写法同 DSH 自带的 cordis 预设）
    bundledSkillDir: !!js >-
      process.getBuiltinModule('node:path').join(process.getBuiltinModule('node:path').dirname(process.getBuiltinModule('node:module').createRequire(baseUrl).resolve('dsh-learn-preset/package.json')),
      'skills')
    customSkillDirs:
      - !!js dshHomePath('learn-skills')
      # learn use 切换课程时，.current 改指向那门课（Windows 上是目录联接）
      - !!js dshHomePath('learning') + '/.current/skills'
```

skill 直接从安装好的包里读，不复制、不同步；升级包之后 skill 自动是新的。目录暂时不存在也没关系，DSH 会等它出现再扫描。

**加 skill 的两种方式，都不用改配置：**

- **跟 AI 说**：例如「把我全局那个 X skill 也给学习用」，或「这门课加一个专门出题的 skill」。AI 先问清只给这门课用还是所有课都用，然后调 `learn skill add` 把现成的 skill 复制过去，或者新写一个。
- **手动**：把 skill 文件夹直接放进上面任一目录。

DSH 会监视这些目录，skill 放进去下一步就能用，不用重启，也不用开新会话。

### 2.5 脚本怎么跑

不要求用户另装 Node。人设里给的命令是启动器，由它找能用的 Node：

| 平台 | 人设里写的命令 |
|---|---|
| macOS / Linux | `sh "$DSH_PROFILE_DIR/node_modules/dsh-learn-preset/bin/learn" <子命令>` |
| Windows | `& "$env:DSH_PROFILE_DIR/node_modules/dsh-learn-preset/bin/learn.ps1" <子命令>` |

启动器按顺序尝试：
1. DSH 桌面版注入的 `DSH_DESKTOP_NODE_EXECUTABLE`（以 `ELECTRON_RUN_AS_NODE=1` 运行）
2. PATH 里能用的 `node`
3. macOS 上 DSH 安装包自带的 Node（`/Applications` 或 `~/Applications` 下）

都找不到就报错退出（127），模型把错误原文告诉用户。

不能直接写 `node learn.mjs`：DSH 自带的 `runtime/bin/node` 是个包装脚本，离开桌面版注入的环境变量会报 `exec: : not found`。

## 3. 学习档案

**所有课程的进度都放在一个固定位置**：`~/.dsh/learning/`，和你在哪个工作区、开哪个会话窗口都无关。

```
~/.dsh/learning/
├── .git/                    每次写入自动提交：完整历史，可回滚
├── .gitignore               排除临时文件和这台电脑的同步状态；没连同步仓库时也排除画像
├── .sync.json               这台电脑的同步状态（不进 git，见 §3.4）
├── .local.json              这台电脑在学哪门课（不进 git：两台电脑可以各学各的）
├── index.json               课程清单 + 最近在学哪门（以 .local.json 为准）
├── profile.json             学习者画像：跨课程记录用户会什么（没连同步仓库时不进 git，见 §3.3）
├── python-async/
│   ├── state.json           唯一的真实状态：目标、计划、每节状态、步骤进度、疑问、错题、复习日期
│   ├── log.md               学习日记，只往下追加，给人看
│   └── skills/              只给这门课用的 skill（见 §2.4）
└── rust-basics/
    └── ...
```

练习代码写在哪都行（当前工作区、临时目录），不影响进度定位。

**为什么不按工作区存：** 学习是跨天、跨窗口的。如果进度跟着工作区走，换个窗口、换个文件夹开会话就找不到了。放在固定位置，任何用学习预设打开的会话都能找到。

### 3.2 先修相关字段（v0.3）

```json
{
  "goal": { "profileSkill": "Spring Boot REST 开发" },
  "forPrereq": null,
  "prereq": {
    "setAt": "2026-10-14T17:51:04+08:00",
    "none": null,
    "asked": 2,
    "quizSeq": 1,
    "qStart": 0,
    "batchNo": 1,
    "batchKind": "intake",
    "items": [
      { "name": "Java", "role": "core", "reason": "写控制器和实体类", "cue": "pom.xml", "source": "intake", "batch": 1,
        "state": "done", "answer": "A", "quizLevel": "mastered", "decision": "known" },
      { "name": "SQL", "role": "core", "reason": "写 Repository 查询", "source": "intake", "batch": 1,
        "state": "done", "answer": "C", "decision": "learn-first", "recommend": "learn-first" }
    ]
  },
  "lessons": [
    { "id": 1, "kind": "prereq", "prereqSkill": "SQL", "requires": [], "uses": [] },
    { "id": 2, "kind": "main", "requires": [1], "uses": ["Java", "SQL"], "forced": false }
  ],
  "mistakes": [ { "id": "m1", "from": "Java", "graduated": false } ]
}
```

- `goal.profileSkill`：结业后记进画像的技能名，范围和终点考核一致。
- `forPrereq`：这门课是为另一门课的先修单独开的（`learn init --for <课程>:<技能>`），结业时自动解除那门课的等待。
- `prereq.items[].role`：`core` 必需 / `general` 有帮助 / `related` 可类比。
- `prereq.items[].state`：`ask` 待问会不会 / `quiz` 待出验证题 / `decide` 待定怎么补 / `done` 已定。
- `prereq.items[].decision`：`known` 已会（有帮助的项显示为「够用」，不验证）/ `anchor` 可拿来打比方 / `dropped` 不拿来打比方 / `learn-first` 先补 / `inline` 边学边补 / `separate` 先单独学一门 / `skip` 跳过。`note` 记脚本替用户定的原因（如「自述能独立做，名额用完没验证」）。
- `prereq.items[].source`：`intake` 出计划前 / `append` 分阶段追加 / `gap` 课中发现缺。
- `prereq.asked`：累计记过几次「会不会」；`quizSeq`：累计出过几道验证题。两个都只增不减，画像证据的 ref 用它们编号。
- 验证题按批计数：首次列清单、每次 `--append` 各一批（上一批还有项在问会不会或等出验证题时，追加的并入上一批；只剩待定怎么补的项不算没定完）。课中缺口（`gap`）不属于任何一批。`batchNo` 是当前批号，每项的 `batch` 记它属于哪一批，`qStart` 是本批开始时的 `quizSeq`。每批最多 4 道验证题，「会不会」和问怎么补都不计数。
- 「会不会」：本批待问的项一次列给模型，放进同一次提问；记过一项以后，「下一步」改成「刚才那次提问里答过的直接记，不要再问」。问怎么补同理。验证题：一次只给一项，记下再给下一项。
- 名额分配：本批要出题和已经出过题的项，按「必需第 1 项 → 可类比第 1 项 → 其余必需 → 其余可类比」排定顺序（出过题的项也占着位置；答 C 没进验证的项不占）。「会不会」都记完后，排不进剩余名额的项由脚本直接定：必需项进「待定怎么补」（推荐边学边补），可类比项不拿来打比方，`note` 都记「名额用完没验证」，「下一步」前面加一句让模型告诉用户。这一步在每次读档案时做，结果是确定的，各命令看到的状态一致。
- 「会不会」没记完时 `prereq quiz` 拒绝：名额要等这一批的会不会都记完才分。
- 名额用完没验证的项，用户坚持说会：出 1 题 `profile verify` 记下，再 `decide <技能> known`。必需项改成已会，可类比项改回可拿来打比方；备注改成「后来验证过会了」。
- 选了「先补」后又改成别的：路线里这个技能没学完的先修节不再需要，`prereq` 和 status 都提示「不要开讲，用 set-plan 去掉」；`set-plan` 去掉先修节时，别的节 requires 里的这个节号自动去掉。已经学完的先修节可以留在路线里。
- 名额用完由脚本定掉的项，名字记进 `prereq.untold` 存档，下一次给「下一步」时让模型告诉用户，说过就清掉（只看 status / prereq 也算说过）。
- `prereq.plannedBatch`：`set-plan` 排路线时记下当前批号。追加的那批先修定完后，批号和它不一样才提示「排新阶段的节」。
- v0.3 的旧档案没有 `batch` / `qStart` / `batchNo`：读的时候补上。有在问会不会或等出验证题的项时，最早一个这样的项之后加的都算当前这批，`qStart` 取累计题数减去这批已出的题数；没有（只剩待定怎么补的也算没有）就从当前累计数开始算下一批。
- 课程档案只存用户选的字母和档位，题目细节只存在画像里。
- `lessons[].kind`：`prereq` 先修节 / `main` 正课。选了「先补」的技能必须有 1-2 节先修节；`uses` 里写了这个技能的正课，脚本自动把先修节加进它的 `requires`。
- `lessons[].forced`：前置节没学完就用 `--force yes` 开始的节，学完时清掉。
- `mistakes[].from`：这个误解来自用户会的哪个技能（按旧习惯做错的），复习时出专门的题。`graduated`：复习过关移出错题本；教学中又犯同一个错用 `review --fail` 打回。

### 3.3 profile.json：学习者画像

```json
{
  "_readme": "学习者画像，由 learn 脚本维护，不要手改。…",
  "version": 1,
  "enabled": true,
  "seq": { "s": 2, "e": 3, "v": 0 },
  "skills": [
    {
      "id": "s1",
      "name": "Java",
      "aliases": [],
      "evidence": [
        { "id": "e1", "type": "self", "level": "mastered", "at": "2026-10-14",
          "course": "spring-boot", "ref": "prereq-a1", "detail": "先修问答选 A" },
        { "id": "e2", "type": "quiz", "level": "mastered", "at": "2026-10-14",
          "course": "spring-boot", "ref": "prereq-q1", "detail": "预测 equals 与 == 输出并说出原因" }
      ],
      "createdAt": "2026-10-14T17:51:04+08:00",
      "lastUsedAt": "2026-10-14T17:51:04+08:00"
    }
  ],
  "createdAt": "2026-10-14T17:51:04+08:00",
  "updatedAt": "2026-10-14T17:51:04+08:00"
}
```

- 证据 `type`：`self` 自述 / `quiz` 题目验证 / `lesson` 先修节通过 / `course` 结业。只追加，档位由脚本读的时候按固定规则现算（规则见 [方法论.md](方法论.md) §13.1），文件里不存档位。证据的先后按日期 `at`、再按记录时刻 `ts`（UTC，v0.4 起才有，旧证据算当天最早）、再按编号排，不看数组顺序，所以两台电脑的证据合并后，在哪台合并算出来的档位都一样。
- 同一条记录重复写（比如命令重跑）只记一次：来源编号 `ref`、课程、类型、档位、说明都相同才算重复。
- 技能名按内置别名表归一：大小写、空格、点和连字符不区分，`js` 和 `JavaScript`、`k8s` 和 `Kubernetes`、`C` 和 `C语言` 算同一个；`C`、`C++`、`C#` 保持不同。模型不能自己加别名。技能名不超过 40 字。
- 上限：最多 50 个技能（满了拒绝写入，并列出最久没用的 5 个让用户删）；每个技能最多 8 条证据，超了先丢最旧的自述，没有自述再丢最旧的验证（刚写入的那条和结业证据不丢）；`detail` 不超过 120 字。
- 写入校验：拒绝邮箱、手机号、身份证号，报错时引出命中的那段文字；`detail` 里不准出现「精通」「专家」「完全掌握」「熟练掌握」「完全理解」「完美」（用户原话放在「」里可以）。读取时逐条校验技能和证据的字段，格式不对按坏文件处理：先从备份恢复，备份也坏就本次按空画像读、拒绝写入。
- 写入安全：加锁文件 `profile.json.lock` 防止两个会话同时写（10 个并发写入实测不丢）；写之前先把旧文件备份成 `profile.json.bak`，读到坏文件时从备份恢复。`profile forget` 删除后连备份一起覆盖，删掉的条目不会从备份里回来；`profile reset` 删掉画像和备份，原来是暂停状态的保持暂停。开了同步时，从仓库拉下来的画像变了（包括别的电脑删了条目或清空了），这台的备份跟着更新或删掉，不会在画像文件坏了时把删掉的条目恢复回来。
- 当前课程的先修问答里待问或待验证的那项技能，`profile add / verify` 拒绝，回答要用 `prereq answer / quiz` 记；其他技能照常可记。
- 画像写失败不影响主命令：课程进度照常记录，输出里多一行「⚠ 画像未写入：…」。
- 没连同步仓库时，三个文件都写进 `~/.dsh/learning/.gitignore`，不进 git 历史，`profile reset` 删掉就是真的删掉。
- 连了同步仓库（§3.4）后，`profile.json` 进 git、随进度一起同步（备份和锁文件仍不进）。这时 `forget` / `reset` 删的是当前版本，同步仓库的历史里还留着删之前的版本；脚本的输出和 `learn-profile` 都会这样告诉用户。

### 3.4 多台电脑同步（v0.4）

整个 `~/.dsh/learning/` 本来就是 git 仓库，每次写入都自动提交。`learn sync --remote <地址>` 给它加一个远程（建议用 GitHub 私有库），公司和家里的电脑就能接着学同一份进度和画像。

- **拉：** `learn status`（每个新会话第一条命令）每次先拉；其他命令距上次尝试超过 5 分钟、或上次推送被拒时先拉。上次没连上时放宽到 30 分钟，免得断网时每条命令都等。没连上就用本机进度，status 开头说一句。
- **推：** 有新提交就在后台推（另起一个进程，不让用户等），只推那条命令写完时的提交；前一个推送还没完就排队等它，连着几条命令也不漏推。`pause` / `finish` 当场推，输出「已推到同步仓库」或「没推上去（原因）」；被拒是因为另一台刚推过时，先拉下来合上再推一次。
- **合并：** 两边都有新记录时，不改写任何一边的历史（不用 rebase，也不靠 git 的按行合并），由脚本比较分叉点、这台、仓库三份内容算出合并结果，生成一个同时接着两边的合并提交，再正常推上去。课程目录整门课比：只有一边改了取那边，两边改得一样随便取。`index.json` 和 `profile.json` 按内容合：课程列表两边都留，同一门课取最近活动的那份；画像三方合并，两边新加的技能和证据都留，基线里有、任一边删掉的去掉，技能剩不下证据才删；暂停：只有一边改了就听那边的，两边都改了以暂停为准，所以在一台电脑上说「别用画像」，别的电脑合并后也暂停。`.gitignore` 两边取并集。合并结果里已经没有目录的课程（一边删了课、另一边没动），课程清单里也去掉。系统自己生成的文件（`.DS_Store`、`._*`、`Thumbs.db`、`desktop.ini`）不进 git、合并时不看，打开过课程文件夹不算改了这门课。合并结果先生成提交，动工作区之前在 `.git/learn-merge-pending.json` 留个记号，再更新工作区，最后挪分支：分支挪不过去（比如 git 的锁还在）就把工作区退回合并前；进程在中间被杀，下一条命令按记号把合并补完（工作区里既不是合并前、也不是合并结果的内容先存进备份分支 `backup/interrupted-…`）。这台有改动没能提交进 git 时不拉，免得冲掉（课程目录里另放的 git 工作副本里面的改动不算）。
- **画像 id：** 开了同步后新记的技能和证据 id 后面带这台电脑的 3 个字母（如 `e12kqx`，记在 `.local.json`），两台各自新记也撞不上号。开同步之前记的老证据 id 两边撞了（同一个编号、记的是不同的证据）时，两条都换新号，旧号作废；技能 id 撞了，仓库那边的换新号。所以合并后编号可能变：`profile forget` 开了同步时必须带技能名，脚本核对 id 存在、又属于这个技能才删，否则列出现在的编号让模型核对，不会按旧号删错。
- **当前课程：** 每台电脑自己记（`.local.json`，不进 git），同步不会把这台正在学的课换掉。
- **冲突：** 同一门课两边都改了、内容又不同（`state.json` 每次记录都变，同一门课不拼两份进度）。合并时把这样的课程一次列全（两边记录没有共同起点时，两边都有、内容不同的课程都算），有就不合并，status 开头给出「⚠ 同步冲突」，点名是哪几门课，列出两边各多出几条、最近几条是什么。选之前什么都不合：这台看不到仓库里的新记录，这台新记的也推不上去，提示里会说。用户选 `sync --keep remote`（这几门课用仓库的）或 `sync --keep local`（用这台的）时，先重新拉一次再算名单：名单变长了（选之前两边又改了别的课）就什么都不动，报新名单让用户重新选；已经不冲突了（或仓库删掉重建了）就照常同步；名单没变才合并，只有名单里的课程（连同课程清单里这门课的标题等信息）取选的那边，其余课程和画像照常合，再正常推送（不强推，另一台照常拉）。被替换掉的那份存进本机的备份分支 `backup/…`，不会丢。冲突没解决时照常记录，每条写命令提醒一句；仓库那边的分支没了，冲突自动解除。合并因为别的原因失败（不是课程冲突）只提示一句，下次再试。
- **第一次连：** 先清掉以前连过的仓库留下的远程分支记录再拉。仓库是空的，把这台的推上去；这台还没学过，直接用仓库里的（这台说过暂停画像的保持暂停）；两边都有记录，先试着合，合不了按冲突处理。仓库里已经有东西、但不像学习记录的（根目录的 `index.json` 不是本脚本的课程清单，或有子目录里没有 `state.json`），拒绝连接。连不上、推不上去（仓库拒收、没权限等），都退回连之前的样子：合并进来的别的电脑的课程从工作区退掉，提交、分支名和上游设置退回连之前；原来没开同步的撤掉远程、画像也不进 git；原来连着别的仓库的，恢复原来的地址和同步状态，照常同步。只有「另一台刚推过、要先拉」这种被拒保持连着，之后自动拉了再推。两边已经一致时直接说一致。拉取的历史再长也不逐条重放，几百条记录的仓库连接也在几秒内完成。
- **只认自己连的仓库：** 连成功后 `.sync.json` 记下 `enabled`、地址和分支；数据目录里原来就有的 origin、或 origin 被改成了别的地址，都不算开了同步，不拉不推。
- **并发和中断：** 每条命令都在数据目录锁 `.learn.lock` 里跑（先写临时文件再硬链接过去，拿锁是原子的；记着进程号，进程已退出、超过 10 分钟、或内容不是进程号且超过 5 秒算失效；清理失效的锁要先拿接管锁 `.learn.lock.takeover.tmp`，清之前再核对一遍还是那把失效的锁，不会删掉别人刚拿到的），两个学习窗口同时用时排队，合并和写进度不会撞在一起。进程被杀留下的 git 锁文件和合并用的临时索引，超过 2 分钟没人动就清掉。数据目录停在 rebase 中间（旧版脚本或手动 git 留下的）时先退回，退不回去就拒绝写入并说明要手动处理。后台推送不拿这把锁，只推它启动时的那个提交；正在合并、不在正常分支、或有没提交的改动时不推，前台收尾时说明原因。
- **不受用户 git 配置影响：** 这台电脑的 git 没设用户名和邮箱时，学习记录的提交用固定署名 `learn <learn@localhost>`；用户全局开了提交或推送签名（`commit.gpgSign`、`push.gpgSign`）、配了钩子（`core.hooksPath`），学习记录的提交和推送也不签名、不跑钩子，不会因此卡住。真提交失败时输出里说一句。
- **安全：** 地址里带用户名、密码或 token 的拒绝，登录交给这台电脑的 git（SSH 密钥或系统钥匙串）。联网的 git 命令不弹密码提示（`GIT_TERMINAL_PROMPT=0`；用户没设 `GIT_SSH_COMMAND`、`GIT_SSH`、`core.sshCommand` 时 SSH 加 `BatchMode`），拉取 15 秒、推送 30 秒超时。连不上、推不上去时，提示里引 git 输出里最能说明原因的那一行（仓库拒收、仓库不存在、没权限、连不上主机）。
- **状态文件：** `.sync.json` 记是否开了同步、地址和分支、上次尝试和成功拉取的时间、上次推送的错误、是否要先拉、没解决的冲突；`.sync.lock` 防止两个进程同时推；`.local.json`、`.learn.lock` 见上。都不进 git。拉取用 `fetch --prune`，仓库删了重建也不会拿旧的远程分支做判断。
- **不做的：** 不自动合同一门课的两份进度；不强推；没有断开同步的命令；备份分支只在本机。

## 4. `learn` 脚本

`bin/learn.mjs`（只用 Node 内置模块）加两个启动器 `bin/learn`、`bin/learn.ps1`，随预设一起打包。模型**不直接改 state.json**，一律通过它，脚本保证格式正确，并顺手完成后续动作。

| 命令 | 做什么 | 谁在什么时候调 |
|---|---|---|
| `learn init <名> [--title "…"] [--for <课程>:<技能>]` | 在 `~/.dsh/learning/` 下建课程目录、写空的 state.json；第一次运行时 `git init`。`--for` 表示这门课是另一门课选了「先单独学一门」的那项先修，结业时自动解除那门的等待 | F1 开始时 |
| `learn use <名>` / `learn list` | 切换当前课程 / 列出所有课程 | 用户想学别的课时 |
| `learn status` | 输出接续信息，见 §5.2；还没立目标 / 还没出计划时只给「下一步」 | 每次开场 |
| `learn now` | 只输出一行位置条 | 一轮回复里进度没变时 |
| `learn set-goal --json '…'` | 写入目标；必须有终点考核 `exam`，可带 `profileSkill`（结业后记进画像的技能名）。已有路线时再调用算重定目标，输出接下来要补的步骤 | F1 结束时、目标变了时 |
| `learn cues [--dir <目录>]` | 只读项目清单文件（package.json、pom.xml、go.mod、CMakeLists.txt、*.csproj 等），列出「技术 ← 文件」；package.json / composer.json 只看依赖字段，标「依赖里有它」，其余标「文件里提到它」。只用来提问 | 先修第一步 |
| `learn prereq set --json '[…]' [--append]` / `--none "<理由>"` | 写入先修清单（必需最多 3、有帮助最多 2、可类比最多 2，每项要写本课用它做什么）；对照画像，能定的直接定；`--append` 用于分阶段展开 | 先修第一步、展开新阶段时 |
| `learn prereq answer <技能> <A\|B\|C\|D>` / `--json '[…]'` | 记「会不会」的回答（D 不确定不记进画像），输出下一步。一次问了几项用 `--json` 一起记：整批校验，有一项不合法就都不记；只输出一张清单和一行合并的画像回执，某项写不进画像（如画像满了）不连累别的项。必需项选 C 推荐先补，选 A / B / D 都要出验证题（分不到名额的转成问怎么补）；可类比项选 A / B 出验证题；有帮助的项选 A / B 算够用，不验证 | 先修问答 |
| `learn prereq quiz <技能> <档> --detail "…"` | 记验证题结果，写进画像 | 先修问答 |
| `learn prereq decide <技能> <决定>` / `--json '[…]'` / `--all-recommended` | 记怎么补：先补 / 边学边补 / 先单独学一门 / 跳过；几项选得不一样用 `--json` 一起记（整批校验）。选「先单独学一门」后输出新开那门课的 `init --for` 命令 | 先修问答最后一步 |
| `learn prereq decide <技能> known` | 用于待定怎么补（如名额用完没验证的必需项）、「先单独学一门」、或名额用完没验证的可类比项（改回可拿来打比方）：用户后来验证过会了，画像里最近一次验证在 180 天内（题目、先修节或结业）、在「会一点」以上、没有降档待复核才放行，改成已会、解除等待；画像暂停时拒绝。通过 decide 改成的已会还能再改 | 等待先修、或用户说「我会，考我」验证过之后 |
| `learn prereq gap <技能> --reason "…" [--lesson <节>]` | 课中发现缺本课以外的技能，加进清单，直接问怎么补（不问会不会、不出验证题），并把技能记进那一节的 `uses` | F4、F6 |
| `learn prereq` | 看先修清单和下一步；早期建的课（有路线、没有先修问答）提示不用补做，需要时用 `--append` 或 `gap` | 随时 |
| `learn baseline --json '[…]'` | 写入摸底结果，每条要有 `evidence`；按能力合并，同名覆盖、其余保留 | F2 结束时、重定目标补摸底时 |
| `learn plan` | 输出当前完整路线（id、标题、类型、依赖、`uses`）、最大 id 和每节状态 | 调整计划前 |
| `learn set-plan --json '…'` | 写入或替换路线，校验节号、依赖存在且不成环；先修问答没做完拒绝；选了「先补」的技能必须有先修节（`kind: "prereq"`），`uses` 里写本节用到的先修。调整时：已有记录的节被改了标题或类型拒绝（防止改号错位，提示最大 id，只是改名加 `--force yes`）；漏掉已有记录的节拒绝；省略 `uses` 沿用原来的；进行中的节新加了没学完的前置节，先暂停（步骤保留） | F3、F6 结束时 |
| `learn start <节> --method --criteria --check --steps '[…]'` | 细化这一节并标为进行中，输出达标标准和检验方式（正课还给出类比格式）。前置节没掌握拒绝，除非 `--force yes`；已做过步骤时不许重新拆步骤（除非 `--force yes`）；复习节必须给 `--steps`。从另一节切过来：那一节步骤全做完还没检验就拒绝，没做完就标为暂停、步骤保留 | F4 开始一节时 |
| `learn step <节> <步> --result "…"` | 这一步标为完成，下一步自动变为进行中，返回新的位置条；只做了一半加 `--partial`。这一节不在进行中时拒绝（要先 `start`） | 每做完一小步 |
| `learn check <节> [--reason "…"]` | 用户说这节会了、想跳过：讲解和练习的步骤记成「跳过」，位置条指到检验那一步（没有检验步就加一步「直接检验」，需复习的节追加一步）；另一节做到一半就先暂停它。这次检验记上 `direct`，教法效果统计不算它；没过时问用户要不要学这一节 | 用户说「这节我会了」 |
| `learn switch <节> <教法> "<原因>"` | 记录换教法，可同时用 `--steps` 换掉没做的步骤。正在检验那一步时拒绝（先 `done --fail` 判完，`--force yes` 强制）；换过一次后提示一节最多换一次，第二次起提示「已经换过 N 次，不要再换」，并给出 `learn split`。换的次数只数真换了的，复习重开时清零 | §7.3 触发时 |
| `learn split <节> --keep "…" --criteria "…" --json '[{"title":"…","summary":"…"}]' [--steps '[…]']` | 一节太大、只卡在一块：本节改名为留下的部分、达标标准改成只考它；还有没做完的讲解或练习步骤时必须用 `--steps` 重给剩下的步骤，只剩检验时换成「检验：只考 …」。拆出去的节用新 id（避开错题和疑问用过的节号）接在本节后面依次学，原来依赖本节的节改成等拆出去的最后一节；拆出去的节在 status 里带着拆之前没过的检验、错题和拆的时候写的 summary。拆过的节「连续 2 次未达标」只数拆完以后的检验。已掌握的节拒绝；本节有达标标准却没给 `--criteria` 拒绝；先修节拆完超过 2 节拒绝。拆完列出本节还记着的错题，提示把属于拆出去那块的用 `learn mistake <id> --to <节>` 挪过去 | 检验只卡在一块，换过一次教法还卡，或用户说这节太大 |
| `learn done <节> --pass\|--fail --note "…"` | 记录检验结果，通过则标为已掌握；没有 `--note` 拒绝。没过时把检验那一步记完，追加补练步骤（`--steps` 指定，不给就追加「补练没过的那一项 → 重新检验」）；达标标准有几项时加一句「如果只卡在一块就 `learn split`」；连续 2 次没过提示换教法（已经换过就提示别再换）。`learn step` 记完检验那一步时提示直接 `done` 判定 | F4 检验之后 |
| `learn ask "…"` / `learn answer <qid> "…"` | 记疑问 / 标为已解决 | 用户提问时 / 确认懂了时 |
| `learn mistake <节> "<错的理解>" "<对的理解>" [--from <技能>]` | 记一条错题，1 天后到期；`--from` 标出是按哪个已会技能的习惯做错的 | 发现错误理解时 |
| `learn mistake <错题id> --to <节>` | 把错题挪到别的节；那节还没检验过，这条错题就等那节检验过一次（或学完）再复习。只是整理记录，不算一次学习（不开新的学习记录） | 拆节后，把属于拆出去那块的错题挪过去 |
| `learn due` | 列出今天到期的错题（最多 5 条）；挪过去、还在等那节检验的错题不列 | F5、定时提醒触发时 |
| `learn review <错题id> --pass\|--fail` | 通过则进下一档，不通过则回到 1 天。没到期、已移出错题本、或挪过去还在等那节检验的不能 `--pass`；已移出的 `--fail` 会放回错题本 | F5 复习时、教学中又犯同一个错时 |
| `learn review --lesson <节> --reason "…"` | 把一节标为需复习；依赖它、正在进行的节先暂停 | 久没学摸底不过、前置节没学会时 |
| `learn pause --summary "…" --next "…"` | 收尾：这次学得怎样、下次从哪开始 | 用户要走时 |
| `learn finish --pass\|--fail --note "…"` | 结业考核结果；通过时把 `profileSkill` 以结业证据记进画像。在等这门先修的课（`init --for` 关联的，或先修名对得上的）自动解除等待：那门课的这项记为已会，画像里给这项先修记一条「会一点」的结业证据 | F7 |
| `learn profile` | 原样列出画像，每条带 id、来源、日期 | 用户问「你记得我什么」 |
| `learn profile add <技能> <档> --quote "<原话>"` | 用户说自己会得更少时直接采信 | 用户纠正 |
| `learn profile verify <技能> <档> --detail "…"` | 用户说自己会得更多，出 1 题后记结果 | 用户纠正 |
| `learn profile forget e<N>\|s<N> --name "<技能名>"` | 删一条证据 / 删整个技能。带 `--name` 时核对 id 属于这个技能才删，对不上就列出现在的 id；开了同步时必须带（合并可能改编号） | 用户要删 |
| `learn profile off` / `on` / `reset --confirm yes` | 暂停 / 恢复 / 清空画像 | 用户要求时 |
| `learn skill add <来源路径> --global\|--course` | 把一个 skill 复制到 `~/.dsh/learn-skills/` 或课程目录的 `skills/` | 用户要求加 skill 时 |
| `learn sync --remote <地址>` | 连同步仓库，见 §3.4：仓库空就推，这台没学过就拉，两边都有就合，合不了让用户选 | 用户想在别的电脑上接着学 |
| `learn sync` | 当场拉一次、推一次，报告同步状态 | 用户问同步了没有 |
| `learn sync --keep local\|remote` | 同步冲突时，冲突的课程留哪边；另一边存进备份分支，其他课程和画像照常合并 | 用户选完之后 |
| `learn help` | 列出全部用法 | 模型忘了参数时 |

**每个写命令执行完都会自动做两件事：**
1. 往课程目录的 `log.md` 追加一行人能看懂的记录
2. `git commit`，提交说明就是这条记录

连了同步仓库时还会推上去（§3.4）。

所以模型只要记得调用一条命令，日志和历史都不会漏。

**写进画像的命令**（`prereq answer` / `prereq quiz` / `profile add` / `profile verify`、先修节 `done --pass`、`finish --pass`）会多输出一行「画像：已记入「Java」e2（题目验证：已会），现在算已会…。不对就说「删掉这条」」，模型原样转告用户。第一次写入时还会说明画像文件的位置。先修问答和先修节的回执放在输出最后，前面一行写明「把下面的画像回执一字不改贴给用户」：实测光靠人设，模型常常不转告、改写，或者用 `tail` 截掉。

**先修问答由脚本带路：** `prereq set` 之后每条 `prereq` 命令都输出「下一步」，写明问谁、问什么、用哪条命令记录，模型照做即可：「会不会」一次列出本批所有待问项，验证题一次只给一项，并写明「ask_user_question 里只放这一题」和判档规则。问多少题、推荐哪个决定都由脚本对照画像算出来。

## 5. 跨会话接续

要解决的场景：昨天在一个窗口学到一半，今天在另一个窗口问「下一步学啥」，模型必须知道上次学到哪、学得怎么样、还有什么没解决的疑问。

### 5.1 学的时候随时记，不等一节学完

只在一节结束时记录是不够的：你可能学到一半就关了窗口，那这半节课就什么都没留下。所以分四种时机记录，每种都是一条命令：

| 时机 | 命令 | 记什么 |
|---|---|---|
| 每做完一小步（10-15 分钟一次） | `learn step <节> <步> --result "..."`（只做了一半加 `--partial`） | 这一步的结果：做对了、错在哪、表现如何 |
| 你提出一个疑问 | `learn ask "<疑问原话>"` | 疑问当场入档，状态为「未解决」 |
| 疑问被解答且你确认懂了 | `learn answer <疑问id> "<一句话结论>"` | 疑问标为已解决 |
| 你说下次再学、时间到了 | `learn pause --summary "..." --next "..."` | 这次学得怎样、下次从哪开始 |

这样即使你直接关窗口，最多丢掉正在做的那一小步，前面每一步的结果和每个疑问都已经记下了。

### 5.2 新会话的第一件事

人设里写死：**会话开始后，回答你任何问题之前，先运行 `learn status`。** 不管你第一句话问的是「下一步学啥」「继续」还是别的什么。

`learn status` 读 `~/.dsh/learning/`，输出一段给模型看的精简接续信息：

```
当前课程：python-async「Python 异步并发」（另有：rust-basics（9 天没学））
目标：写一个并发抓 20 个网页的脚本，并解释为什么比串行快
进度：7 节中已掌握 2 节；当前第 3 节「异步函数的执行顺序」，教法：诊断纠偏（加载 skill teach-diagnose），第 2/4 步「纠偏」进行中
上次（2 天前，10-14 20:30–21:30）：做完探测和一半纠偏，对「阻塞」概念还模糊
上次说好的下次起点：从第 3 节第 2 步继续，先回答 q1
未解决的疑问：
  q1「那 time.sleep 放在 async 函数里会怎样？」（10-14 提出，第 3 节）
今天到期复习：1 条（m1：以为 await 会阻塞整个线程）
📍 第 3 节「异步函数的执行顺序」 · 第 2/4 步：纠偏 · 下一步：变体题 2 道
```

视情况还会多出这些行：
- 目标行带上「每次约 N 分钟，快到时收尾」（立目标时给了单次时长）。
- 「本节达标标准：…；检验方式：…」（当前节已细化）。
- 「本节上次检验（未通过）：…」；本节还没检验过时给「最近一次检验（第 N 节，通过）：…」，细化新一节时参考。
- 「本节记过的错：m1「…」」（当前节还在错题本里的错，最多 3 条）。
- 当前节是暂停的（做过几步后切去别的节）：进度行写「已暂停，做完 k/m 步，教法：…（加载 skill teach-xxx）；接着做：learn start N，不带 --steps」。

有先修和画像时还会多几行，例如：

```
边学边补的先修：SQL（第 1 节要用）
可类比（用户会的技能）：Java（已会）。讲本节新概念时，两边真有对应才打比方，按这个格式，缺一行不算讲完：
  〔用你会的 X 打个比方〕
  对应：本课的 … ≈ X 的 …
  相同：1-3 点
  不同：至少 1 点，附最小例子
  别套用：什么情况下按 X 的习惯会出错
（后面还有两句：讲完接正式说法和最小例子，问看懂没有，看懂了再出 1 道针对「不同」的预测题；由此暴露的误解用 --from 记）
默认教法建议：示范例题（跨课程首次检验通过 4/5）
```

- 类比格式只在正课进行中时给全（续学的会话拿不到 `learn start` 的输出）；先修节不给；还没开始的节只列一行「可类比」。
- 默认教法建议只会是练习批改或示范例题（另外两种只按内容选）；画像暂停时不给，改成一行「画像：已暂停」。
- 还没立目标或还没出计划时，status 不显示进度，而是显示先修清单、摸底结果和「状态：还没出计划。下一步：…」；有先修选了「先单独学一门」时多一行「等待先修：…」。
- 上次没正常收尾时，「上次」那几行换成「⚠ 没有正常收尾，以下是最后的记录」加最后两步的结果（见 §5.3）；14 天及以上没学多一行「⚠ 已经 N 天没学：先快速摸底已掌握的节…」。

模型拿到这段之后，第一句回复就能是：

> 上次你学到第 3 节「异步函数的执行顺序」，纠偏做到一半，对「阻塞」还有点模糊，另外留了一个问题：time.sleep 放在 async 函数里会怎样。今天先花 5 分钟把这个问题和 1 道复习题过掉，然后接着纠偏，好吗？

### 5.3 上次没正常收尾怎么办

你直接关了窗口，上次的会话就没有 `pause` 记录。`learn status` 会发现「最后一次会话没收尾」，并用最后一条 `step` 记录和未解决疑问拼出接续信息，同时标出 ⚠。模型开场先跟你确认一句：「上次停在第 2 步中间，那一步要从头做还是接着做？」

### 5.4 多门课

`index.json` 记着每门课和最近一次学习时间。`learn status` 默认显示最近在学的那门，并列出其他课的一句话状态。你说「今天学 rust」，模型就切到那门。

### 5.5 在别的预设里问

如果你在普通会话（没选学习预设）里问「我下一步学啥」，那个会话不知道学习档案。想让它也知道，自己在 DSH 全局指令文件 `~/.dsh/AGENTS.md` 里加一句（DSH 会把这个文件注入所有会话，不管用的是哪个预设）：

```
学习进度在 ~/.dsh/learning。被问到学习进度时运行：sh "$DSH_PROFILE_DIR/node_modules/dsh-learn-preset/bin/learn" status（Windows：& "$env:DSH_PROFILE_DIR/node_modules/dsh-learn-preset/bin/learn.ps1" status）
```

别的预设里没有 `learn` 这个简写，所以要写完整命令。本包不会自动改这个文件。

## 6. 定时复习提醒

开了「自动化任务」时：
- F3 出完计划后，问用户每天几点学习，然后调 `schedule_create`，用 `daily` 规则在这个学习会话里定一条每日提醒。
- 提醒内容固定为：「运行 `learn due` 和 `learn status`，有到期复习就开始复习，没有就继续当前节」。
- 结业时调 `schedule_delete` 删掉这条提醒。

没开时：
- 不报错。开场时由 `learn status` 显示「距上次学习 N 天」和到期复习数量。
- 在 F3 结束时提示一次：「在插件管理里打开『自动化任务』，可以每天定时提醒你复习」。

**判断开没开：** 看当前工具里有没有 `schedule_create`，不需要额外配置。

## 7. 怎么保证模型按规矩来

| 风险 | 防范 |
|---|---|
| 学完一节忘了记录，或开了别的节把它晾着 | 每个教法 skill 的最后一步写死「先调用 `learn done`，再回复用户」。切到别的节时：步骤全做完还没检验的拒绝切走（要先 `done`）；没做完的标为暂停，步骤保留，位置条显示「已暂停，做完 k/m 步」，回来时 `learn start` 不带 `--steps` 接着做 |
| 手改 state.json 改坏 | 人设里明确禁止直接编辑 `~/.dsh/learning/`；脚本每次读取时校验格式，坏了就从 git 上一个版本恢复，并提示用户 |
| 日期算错 | 所有日期都由脚本算，模型不碰 |
| 新会话忘了先查进度 | 人设第一条就是「回答任何问题前先运行 `learn status`」；skill 开头也会检查本会话是否已经运行过 |
| 学到一半关窗口 | 每一小步都记录（§5.1），最多丢正在做的那一步；下次开场会标出没收尾（§5.3） |
| 用户说懂了就过 | `learn done --pass` 要求带检验备注（做对了哪道题、讲清了什么），没有备注脚本拒绝 |
| 对话太长被压缩 | 进度全在文件里，压缩只丢讲解过程，不丢进度 |
| 位置条自己编，和真实进度对不上（实测出现过） | 人设第 6 条：位置条只能原样抄 `learn step` / `learn now` 的输出；每轮回复固定顺序「先记录 → 再写正文 → 最后抄位置条」 |
| 续学时加载了别的教法 skill（实测出现过） | `learn status` 写明「加载 skill teach-xxx」；`learn-review` 要求只加载这个；换教法必须先 `learn switch` |
| 一步做完却记成「进行中」（实测出现过） | `learn step` 默认记为完成，只做了一半才加 `--partial`；不接受 `--status` |
| 摸底选择题的选项说明泄露答案（实测出现过） | `learn-intake` 和人设都要求选项不暗示对错、最后一项固定「不确定」、选对后追问「为什么」 |
| 出完路线没等确认就开讲第一节（实测出现过） | `learn-plan` 要求给出路线后停下，用户确认后才 `learn start` |
| 跳过先修问答直接出计划 | `set-plan` 在先修问答没做完时拒绝 |
| 把用户自述当成已会 | 只有自述时脚本封顶「会一点」，必需项还要出验证题 |
| 模型编造或夸大画像 | 画像只能通过脚本写，只在四种时机写；档位由脚本按证据算；拒绝「精通」这类词；每次写入都给用户回执，可以当场删 |
| 拿项目里出现的技术当成用户会 | `learn cues` 的输出写明「项目用到 ≠ 用户会」，只用来提问；用户回答后才记进画像 |
| 类比讲得太像，用户把旧习惯带进新技能 | `learn start` 给出的类比格式必须写「不同」和「别套用」，再出一道针对差异的预测题；由此暴露的误解用 `--from` 标记，复习时专门出题 |
| 画像里存了隐私信息 | 脚本拒绝邮箱、手机号、身份证号；没连同步仓库时画像不进 git，连了也只推到用户自己的私有仓库，地址里不许带 token；用户可随时查看、删除、暂停、清空 |
| 两个会话同时写画像 | 锁文件 + 写前备份，坏了从备份恢复 |
| 调整计划时给节改了号，记录错位 | `learn plan` 先拿当前路线；有记录的节标题或类型变了就拒绝，提示新节用比最大 id 大的号 |
| 先修选了「先单独学一门」后课程一直卡着 | `learn prereq` 写明三个出口（还没出路线时 status 的「下一步」也会写）：`init --for` 新开那门（结业自动解除）、别处学会了验证后 `decide known`、不等了改 `inline` |
| 课中卡在本课以外的技能上，却当成本课内容硬教 | 人设和教法 skill 都写了：卡在先修上用 `learn prereq gap`，只问怎么补；卡在前置节上用 `review --lesson` |
| 几道题塞进一次提问，脚本只能记第一道（实测出现过） | 「会不会」改成本来就一次问完、不占名额；验证题的「下一步」写明「一次只出这一题，ask_user_question 里只放这一题」，名额由脚本按顺序分 |
| 选择题选对了没说原因，判成「不会」（实测出现过） | 验证题的「下一步」写明判档：选对没说原因是 `partial`，选对后先追问「为什么」再判 |
| 验证题的选项里没有正确答案（实测出现过） | `learn-intake` 和脚本输出都要求有且只有一个选项是对的，出完先自己核对 |
| 换了电脑进度对不上，或两台电脑各记各的 | `status` 每次先拉，记录后自动推，收尾时当场推并报告结果；同一门课两边都改了不自动合，给出两边的差异让用户选，另一边存进备份分支 |

## 8. 会话内和会话间

| 范围 | 用什么存 | 存什么 |
|---|---|---|
| 一节课之内 | todo 工具 | 这一节的 5 步走到哪了 |
| 一次会话之内 | 对话上下文 | 当前讲解、刚做的题 |

## 10. 安装

`dsh` 命令行在 macOS 上位于 `/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh`，没加进 PATH 时用完整路径。

1. 把整个包目录放到一个固定位置，例如 `~/.dsh/local-plugins/dsh-learn-preset/`。
2. **完全退出 DSH 桌面版**（DSH 要求改 desktop profile 时桌面版不在运行）。
3. `dsh plugin --profile desktop add ~/.dsh/local-plugins/dsh-learn-preset`。本地路径以 `link:` 方式安装并登记为 bundle，之后改这个目录里的文件直接生效（改了人设或插件列表要重启 DSH）。
4. 打开 DSH，新建会话时在预设里选「学习教练」。

### 11.4 真实使用反馈：没见过的东西先被提问（2026-10-15）

用户在自己的课（手搓大模型，第 4、5 节 numpy）里反映：完全不会的东西，教练举个例子就开始提问，例子都没看懂，很影响学习心态。对话记录里有 5 次：

| 发生了什么 | 规则里的原因 |
|---|---|
| 第 4 节用户从没碰过 numpy（摸底记的是 `none`），教练却选了第一性原理，先问列表哪里别扭，再问「同一块内存靠什么区分不同读法」；实测脚本只贴了结果，`arr` 凭空出现 | 人设底线「先问后讲」对所有内容都适用；第一性原理禁止「先给结论」。教练依据的是第 3 节收尾时自己写进 summary 的「该用户更适合先问为什么，数学几节默认用 first-principles」，这段话在 status「上次」里每次都显示，而摸底结果出完计划后 status 就不显示了 |
| 换成示范例题后，补全题要用户写出没示范过的二维写法 `np.zeros((3, 4))`（示范的是 `np.zeros(5)`），连猜三轮，第二轮的猜错记成了错题 | 补全题只要求「同类题」，补错只给提示，连错 2 次才退回示范；没讲过的东西猜错被当成误解记下 |
| 第 5 节示范 `axis`：用法表、「把第 0 个轴消掉」的规律、方向、易错点一次给出，紧接着出一道换了形状的确认题 | 示范例题写着「做完问用户一个关于示范的问题，确认看懂了」；人设固定顺序要求每轮「反馈 + 下一个问题或任务」 |

修正：

- 人设底线 3 改成「没见过的先讲，见过的才先问」：不知道用户接触过没有就先问一句；没接触过的先举具体例子、给完整代码和真实输出、最后讲规律，讲完问看懂没有，看懂了才出题，题目只用讲过的词；用户说没看懂，这一轮只换个更具体的例子讲，不出题。底线 2 和固定顺序改成「最多一个问题」，允许只讲不问。没讲过的东西猜错不记 `mistake`。
- `learn-plan`：摸底里没有这节的内容就先问接触过没有，不用内容题探；「从没接触过」排在选教法表第 2 行（动手类和概念都算），用示范例题，上一节哪种教法好用、自己在 summary 里写的「用户适合某教法」都不能盖过它；第一性原理限于用户接触过的内容。`learn-review` 收尾的 summary 只写发生了什么，不写「以后默认用某教法」。
- `teach-worked-example`：先说用途、举生活里的例子再上代码；贴完整代码和输出；一轮只讲一小块；讲完先问看懂没有，看懂了只出改一两个数的同类题；没看懂换更具体的例子重讲，同一块连续 2 次没看懂就问卡在哪一句、哪个词。补全题只能补示范里原样出现过的写法，补错在没示范过的地方直接给正确写法。
- `teach-first-principles`、`teach-diagnose`：用户从没接触过就 `learn switch` 到示范例题。`teach-coach`：任务要用到没见过的写法，先给完整示例。
- `learn-intake` 摸底：可能没见过的库、写法、概念先问接触过没有，没接触过直接记 `none`，不出内容题；依赖它的更深能力不出题也不写进摸底，到那一节开讲前再问（这门课摸底时就问过用户 `x.mean(axis=0)`，用户答「我看不懂」）。

#### 复测（同日晚，DeepSeek-V41-Flash）

隔离环境里预先放了一门「用 numpy 手写线性回归」的课，状态照着出事时布置：第 1 节学完，摸底里没有 numpy，上次的 summary 写着「该用户更适合先问为什么，后面几节默认用 first-principles」。扮演从没碰过 numpy 的学员跑了两个会话。

第一轮（第 2 节「numpy 数组与形状」）：

- 照规则走对的：开讲前先问接触过 numpy 没有，并说明「没见过的东西让你猜是浪费时间」；没被 summary 带偏，选了示范例题；示范按「干什么用 → 成绩表 → 完整代码和输出」讲，结尾问看懂没有，不出题；学员说没看懂，回复写明「这轮我不出题」，换成「数每层中括号里有几个东西」重讲；说看懂了才出题，题只换了数字；补全题要用的 `reshape` 先示范再让填；独立题只考讲过的；猜错没记成错题。
- 还有的问题：讲完 `reshape` 同一轮就出了补全题；讲完「数字 + 数组」的广播，同一轮就让预测「两个形状不同的数组相加」，这是没讲过的新情况。学员说「你没讲啊，我只能猜」后它认错补讲，收尾时自己也说「今天两次都是先出题再补讲规则」。另有几处标着「真实输出」却没跑代码（数字是对的）。

据此补了第二轮修正：

- 脚本：示范例题的节，`learn start` 和每次 `learn step` 进入讲解或练习的一步时，在位置条前多一行「（给教练看，不用转告）这一步如果要用到没讲过的东西……这一轮只讲……讲完只问看懂没有，不出题」。检验那一步、`--partial` 和别的教法不出这一行。
- `teach-worked-example`：讲了新东西的那一轮不出题，选项里带「没看懂」也不行；讲过的东西的新情况也算新东西；输出用 bash 真跑出来再贴；一步里有两个新东西就分两轮讲；拆开算的每个数都要和输出对得上。
- `learn-plan`：每个新知识点有自己的示范步骤（一步只放一个），「你做」只练示范过的。
- 人设底线 3：「讲完这轮只问看懂没有，看懂了下轮才出题」。

第二轮（新会话，第 3 节「axis 与沿轴求和」，就是用户原来卡住的那节）：

- 先问接触过 axis 没有；步骤拆成「示范 sum 的 axis → 一起做 → 示范 mean 和通用规律 → 你做 → 检验」；示范先讲用途和成绩表，再用 bash 跑代码，结尾「这一轮只讲这一块，看懂了吗」。
- 学员用原话「没看懂别急着提问。怎么叫沿第 0 维往下压？为啥 axis=0 反而是每一列加起来」，它换成「方括号层数」和 Python 循环手算对照重讲，结尾只问看懂没有。
- 进到「示范 mean」那一步，脚本提醒生效：只讲不问。
- 还有的问题：这一轮把 `mean`、通用规律和三维数组一起讲了；有一处拆开算的数讲错（输出 `[12 14 16 18]` 是对的，解释写成了另两行相加）。已补「一步里有两个新东西就分两轮」「拆开算的数要和输出对得上」，这两条还没再复测。会话开头调工具前那句仍是英文。

### 11.5 真实使用反馈：一会儿这样一会儿那样（2026-10-17）

用户在同一门课第 5 节「numpy（下）：axis、广播、矩阵乘法」学了两天（10-16 上午到下午、10-17 上午），最后说「好烦啊，一会这样一会那样」，事后反映学得筋疲力尽、不知道怎么办。这次用的已经是 §11.4 改过的规则：先讲后问、看懂了才出题都做到了，axis 讲通了。累人的是下面这些：

| 发生了什么 | 规则里的原因 |
|---|---|
| 一节塞了 axis、广播、矩阵乘法三件互相独立的事，`@` 连示范步骤都没有，是在「你做」那一步现教的 | 这节是 10-15 下午排的，那时还没有「每个新知识点有自己的示范步骤」；「一节只学一个点」没有例子，三件事被当成一个点 |
| 例子表一直在变：上午 `sales` 是 4 行 3 列（行是商品），中午变成 3 行 4 列（行是门店），之后又换成 4×5、2×3、4×3、2×5。同一个 `(3,)` 上午能加，中午报错；用户问「C 又为什么啊，C 可以的话 A 又为什么不行呢，我要晕死了」 | 没有「一节用同一张例子表」这条；独立题、诊断题都要求「换外观」 |
| 检验一次问 4 问，用户要求换个问法后又出 5 问，重讲完整节后再出 5 问；用户说「你一次性问了太多了」「这个问题问了三遍了」。从 12:06 到 16:11，一直停在「费曼检验」这一步里讲课、出题 | 费曼 skill 只写了「先出 1 道新题」，没写一道只考一个点；没写答错就停止检验、记未达标回去补 |
| 半小时里换了两次教法：示范 → 诊断（用户说「换一种教学方式呢」）→ 背口诀（用户说「换一种学法」，从三个选项里选的），补练步骤又混进了没选的「改数字」；诊断是在检验那一步里做的，诊断题做完被记成了检验那一步的结果 | 人设「卡住就换」，没有上限；换教法时没提醒正在检验；没有「拆小一点」这条路可走 |
| 用户说「对我来说还是有点复杂」「我现在脑子有点乱」「不知道咋讲」「我又给看懵逼了」，教练接着加内容、出题 | 没有「用户说累、乱就停下来」这条 |
| 改数字练习一个文件放了 5 个 TODO；批改时把用户做对的 TODO 1 判成错，又道歉；接着把 TODO 2 改成「新建一个文件贴这段代码」，用户这时说了「好烦啊」 | 没有「一次只布置一个任务」「布置了就按原样做完」 |

修正：

- 人设：底线 4 改成「一节一条路」：每节单独选教法，用同一套例子讲到底（同一张表，形状和行列含义不变，要换先明说）。底线 2 加「用户说乱、烦、累：不加新东西、不出题，问要不要停；继续就只做一件最小的事」。「卡住时」改成先缩小（只讲错的那步，在同一张表上取更小的一块），再换教法；一节最多换一次（用户点名的除外），还卡就 `learn split` 把卡住的那块拆出去。用户点名的教法「只按那一种做」。为腾出字数，删了已经写在 skill 和脚本输出里的几处（计划行数、类比格式细节）。
- `teach-feynman`：检验只检验——新题 1 道、只考一个点，达标标准几项就分几轮；新题用本节那套例子，只换数字；某项答错不在检验里讲课、不原样再问，记下接着问下一项，都问完再判；几项里只有一项没过，记完未达标再 `learn split`。
- `teach-worked-example`：一节用同一张例子表，独立题换场景和数字、不换形状；真要换形状单独讲一轮，先说清换成了什么。
- `teach-coach`：一次只布置一个任务；布置了就按原样做完，有问题在原任务上改；批改前先真跑用户的代码。
- `learn-plan`：「一节只学一个点」加了例子（axis、广播、矩阵乘法是三节）；调整计划表加「只卡在一块 → `learn split`」和「用户说换一种学法 → 选了哪种只按那种拆步骤」。
- 脚本：新命令 `learn split`；`learn switch` 在检验那一步拒绝（先判完），换过一次就提示一节最多换一次；status 显示「本节已经换过 N 次教法」、拆开的节显示从哪拆出来；`learn done --fail` 在达标标准有几项时提示可以拆节，换过教法就提示别再换；`learn step` 记完检验那一步提示直接判定。测试 T32（含 b、c），共 32 组 614 项。评审后补了：检验那一步拒绝换教法、换的次数只数真换的（复习重开清零）、拆节时还有讲解步骤就要 `--steps` 重给、拆完后「连续 2 次未达标」只数拆完以后的、先修节拆完不超过 2 节、新节号避开旧错题。在用户这门课的状态副本上试拆过第 5 节（axis 留在第 5 节只差检验，广播、矩阵乘法成为第 12、13 节，第 6 节改成等第 13 节），检验过了之后位置条指到第 12 节，status 带着拆的时候写的卡点。
- 用户同意后拆了真实档案的第 5 节，结果同上。拆完发现两处，又补了：第 5 节那条广播的错题（`(5,)` 当成一列）当天到期，下次开场会先考广播，等于把拆出去的内容又混回来——加了 `learn mistake <id> --to <节>` 把错题挪到第 12 节，挪过去的错题等那节检验过一次再复习（那节没讲完时开场复习不考它），`split` 拆完列出本节的错题提示挪；拆节是在学习会话外做的，多出一条没收尾的学习记录，下次开场会显示「没有正常收尾」而不是上次说好的起点——用 `learn pause` 补了一条收尾，写明这次只调整了计划、下次先考 axis。测试 T32d、T32e（没挪过的错题照常到期，包括直接检验到一半被暂停的节）。
