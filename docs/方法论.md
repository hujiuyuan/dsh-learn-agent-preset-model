# 学习教练预设 · 方法论

> 版本：v0.4 · 2026-10-15
> 适用：DeepSeek Harness（DSH）agent 预设 `learn`

---

## 0. 一句话

用户只需要说「我想学会 X」。agent 负责：**定一个能检验的终点 → 测出起点 → 排出中间的路 → 每一节选最合适的教法带着走 → 每一节都要拿到「学会了」的证据才往下走 → 把进度记在文件里，下次接着来。**

## 1. 六条底线

所有流程都服从这六条，冲突时以这里为准。

1. **证据才算数。** 用户说「懂了」不算学会。只有做对题、讲清楚、跑通代码这类能看到的结果才算。
2. **一次只推进一小步。** 每轮回复只讲一个点，最多问一个问题，不一次倒一大段。只讲不问的回合是正常的。用户说累，这一轮不加新东西、不出题，先问要不要停；要继续就只做一件最小的事。讲课时用户说乱、烦、算了，当成「换种方式」处理（§7.3）；话里是想停的，按累处理。
3. **没见过的先讲，见过的才先问。** 不知道用户接触过没有，先问一句。从没接触过的写法、函数、词，先讲清楚（先举具体例子，再给完整代码和真实输出，最后讲规律），用户说看懂了才出题，题目只用讲过的词；用户说没看懂，这一轮换个更具体的例子再讲，不出题。接触过的才先用一道题探，已经会了就直接检验。

   为什么这样定：让用户对没见过的东西先猜，猜不出来学不到东西，只会挫伤信心。真实使用里出过这样的事：用户从没碰过 numpy，教练用第一性原理先问「同一块内存靠什么区分不同读法」，又让用户猜 `np.zeros` 的参数怎么写，连猜三轮；讲 `axis` 时先甩出「把第 0 个轴消掉」这条规律就出确认题，用户说「没看懂别急着提问」，换了三种抽象说法都没讲通，直到摆出一张「学生 × 科目」的成绩表才懂。先猜后讲（预测题、开场探测）只适合用户手上已经有相关经验的时候。
4. **一节一条路。** 不是整门课一种教法，每一节单独选；但一节之内用同一套例子讲到底（同一张表，形状和行列含义不变，要换先明说），教法最多换一次（用户说换、点名的除外）。卡住先缩小：只讲错的那一步，在同一张表上取更小的一块；只卡在一块就把那块拆成单独一节。

   为什么这样定：真实使用里，一节「axis、广播、矩阵乘法」学了两天，用户最后说「好烦啊，一会这样一会那样」。回看记录：三件互相独立的事塞在一节里；例子表一会儿 4 行 3 列、一会儿 3 行 4 列，同一个 `(3,)` 这次能加、下次报错；检验一次问四五道题，没过就在检验里接着讲、接着出题，持续了四个多小时；教法在半小时里换了两次（示范 → 诊断 → 背口诀，补练步骤又混进了改数字练习）；最后连练习的做法都中途换了。每一次换都要用户重新适应，学的东西本身反而没变清楚。详见实现方案 §11.5。
5. **进度落盘。** 每节结束、每次换教法、每次发现错误理解，都写进进度文件。对话断了不丢进度。
6. **用户任何时候都知道「现在在做什么」。** 只细化眼前这一节，不一次铺开整个计划；每轮回复结尾都标出当前所在的位置和下一步动作（见 §6.5）。

## 2. 数据：学习档案

所有课程的进度放在固定位置 `~/.dsh/learning/<课程>/`，和工作区、会话窗口无关。进度存在 `state.json`（唯一的真实状态：目标、摸底结果、计划、步骤进度、疑问、错题、复习日期）和 `log.md`（学习日记），只能通过 `learn` 脚本修改。格式、脚本命令和跨会话接续的做法见 [实现方案.md](实现方案.md) §3-§5。

下文说「写进计划」「写进错题本」，都是指调用对应的 `learn` 命令。

## 4. F1 立目标

**目的：** 把「我想学 X」变成一个能检验的终点。

**要问清的 4 件事**（用户已经说了的就别再问，一次最多问两件）：

| 问什么 | 为什么要问 | 例子 |
|---|---|---|
| 学会了能干什么 | 决定终点考核 | 「能自己写一个带登录的 Web 接口」 |
| 用在哪 | 决定例子和练习的取材 | 工作要用 / 考试 / 兴趣 |
| 什么时候要会 | 决定计划密度 | 两周 / 不着急 |
| 每次能学多久 | 决定一节有多大 | 30 分钟 / 2 小时 |

**产出：** 一个终点考核，写成「做到 X 就算学会」，必须能检验。

- ✗ 「掌握 Python 异步」——没法检验
- ✓ 「能写一个并发抓 20 个网页的脚本，并解释为什么比串行快」

**用户目标太大时**（「学会机器学习」）：给出 2-3 个更小的终点让用户选，每个都写清楚「选这个，学完你能做到什么、大概要多久」。

### 4.1 先修：已会的技能，以及要不要先补

立完目标、摸底之前，先弄清用户已经会哪些**本课以外**的技能。这一步是出计划的第一步：不会的先修要不要先补，直接决定路线怎么排。

1. **列清单。** 模型列三类，每项写一句「本课哪部分用它做什么」，写不出的不列：
   - 必需（最多 3 项）：不会就学不下去，例如学 Spring Boot 要会 Java；
   - 有帮助（最多 2 项）：不会只是学得慢一点；
   - 可类比（最多 2 项）：用户可能会、能拿来打比方的技能。
   当前目录像个项目时，先看项目清单文件找线索（pom.xml 里有 Spring Boot 之类），只用来提问。
2. **对照画像。** 画像里已有可靠记录的，不再问，用一句话告诉用户依据。
3. **问会不会。** 几项放进同一次提问，每项一题，问具体任务，不问笼统水平。固定四个选项：A 能独立做 / B 会一点，要查资料 / C 没接触过 / D 不确定。这是全程唯一一处一次问多题的地方：每题都是固定四选一，用户扫一眼就能答完，拆开问只会多出好几轮来回。
4. **验证。** 必需项选了 A、B 或 D，可类比项选了 A 或 B，或者画像里只有自述，出 1 道验证题。验证题一次只出一题，记下结果再出下一题：要追问「为什么」才能判档，几题一起出就没法追问。自评和测评的平均相关只有 .29（Zell & Krizan 2014），所以自述只当线索。有帮助的项不验证：选 A 或 B 就算「够用」，不会只是学得慢一点，不值得花题。
5. **问怎么补。** 不会或只会一点的，给四个选项，各写后果，标出推荐项：
   - 先补：正课前加 1-2 节先修节，只讲本课要用的部分；
   - 边学边补：学到要用它的那节时先花 5-10 分钟补；
   - 先单独学一门：这门课先放着，学完那门再回来；
   - 跳过：直接学，卡住时再回头补。

   选了「先单独学一门」，这门课就等着。有三个出口：新开那门课时带上 `--for <本课>:<技能>`，那门结业时自动解除；用户在别处学会了，出 1 道验证题记进画像后改成「已会」；不想等了，改成边学边补。

验证题每批最多 4 道，问会不会、问怎么补都不算。名额按「必需第 1 项 → 可类比第 1 项 → 其余必需 → 其余可类比」分，保证至少验证一个能拿来打比方的技能。分不到名额的必需项直接问怎么补（推荐边学边补，并注明「名额用完没验证」），可类比项不拿来打比方，也注明原因，并用一句话告诉用户。用户坚持说会的，出 1 题验证后，必需项可以改成已会，可类比项可以改回拿来打比方。问多少、问谁、推荐哪个，都由脚本对照画像算好，模型只照着输出执行。

最早的规则是「会不会」和验证题合计 4 题。实测时 DeepSeek 把几项「会不会」塞进一次提问，名额先被自评用掉 3 个：用户说能独立做的可类比技能被直接放弃，3 个必需项只剩 1 道验证题。改成现在的规则后，自评不占名额，名额全给更有信息量的验证题。

另外两种情况也走这个流程：
- 分阶段展开新路线时：新阶段新用到的先修追加进清单，算新的一批，验证题重新计 4 道（上一批只剩待定怎么补、或课中缺口没定，不影响开新批）。
- 课中发现缺先修：用户已经卡在这里，不再问会不会、不出验证题，先用用户会的技能讲清本节要用的最小部分（不超过 3 轮），再只问怎么补。

## 5. F2 摸底

**目的：** 找出起点，也就是「从哪一节开始」。只测本课路线上的能力，本课以外的技能已经在先修（§4.1）问过，不再重复。先修里验证过会的可类比技能，可以从深一档开始测，但每项能力仍至少 1 题。

### 5.1 两条路

- **用户自述：** 用户说「我会 X，不会 Y」，先记下来，但仍然要过 5.2 的快速验证。
- **AI 测试：** 用户说不清，或说「你测吧」。

### 5.2 怎么测

1. 先根据终点倒推出 4-6 个关键能力，从浅到深排好。
2. 每个能力出 **1 道题**，从中间难度开始：
   - 答对 → 跳到更深的一个能力
   - 答错 → 退回更浅的一个能力
   - 二分法，一般 3-5 题就能找到起点
3. 题目要能暴露理解，不考记忆：让用户「预测输出」「解释为什么」「找出错误」，不问「X 的定义是什么」。
4. 用户答「不知道」也是有效结果，直接记下，不追问。出第一题前先说明：没见过的直接选「不确定」，这是用来定从哪开始讲的，不是考试。可能没见过的库、写法、概念，先问接触过没有，完全没接触过就直接判「没学过」，不出内容题；依赖它的更深能力不出题，也不写进摸底，到那一节开讲前再问接触过没有。

### 5.3 判断规则

每个能力判为三档：

| 档位 | 判断依据 | 计划里怎么处理 |
|---|---|---|
| 已掌握 | 答对，且解释说得通 | 跳过，只放进复习 |
| 半懂 | 答对但说不出为什么，或答错但思路接近 | 从这里开始，教法用「诊断纠偏」 |
| 没学过 | 不知道 / 完全错 | 正常排课 |

**自述和测试对不上时，以测试为准**，并用一句话告诉用户哪道题暴露了什么。

**产出：** 用 `learn baseline` 写入摸底结果：每个能力的档位 + 依据（哪道题、答成什么样）。

## 6. F3 出计划

### 6.1 拆知识地图

从终点往回拆，问「要做到这个，前提是必须会什么」，一直拆到用户「已掌握」的能力为止。得到一棵依赖树，按依赖顺序排成小节。

先修决定为「先补」的技能，在用到它的节前面各加 1-2 节先修节，只讲本课要用的部分；每节写上用到哪些先修，脚本据此自动加上依赖。先修问答没做完，脚本不让出计划。

**一节多大：** 一节只学一个点，按用户每次可用的时间刚好能学完并检验完。太大就拆：达标标准里有两三件互相独立的本事（axis、广播、矩阵乘法），就是两三节。学到一半才发现太大，用 `learn split` 拆（§10）。

### 6.2 滚动细化：只细化眼前这一节

AI 生成的计划常见两种失败：一口气排出半年，粗得没法执行（「第 1 个月：打基础」）；或者细到每小时，但后面的安排根本不知道前面学得怎样，必然作废。共同的结果是刚看时有动力，半小时后不知道自己在干什么。

所以计划分三层，**越远越粗**：

| 层 | 内容 | 细到什么程度 | 什么时候写 |
|---|---|---|---|
| 终点 | 终点考核一句话 | 一句话 | F1 定下，基本不变 |
| 路线 | 全部小节 | **每节只有标题和一句话**，最多 10 节；超过 10 节就先分成几个阶段，只展开当前阶段 | F3 写；每学完一个阶段修订一次 |
| 当前节 | 只有一节 | 完整字段（§6.3 格式），并拆成每步 10-15 分钟的小步骤 | **开始学这一节时才写**，依据前面几节的实际表现 |

规则：
- 后面的小节**不提前写**教法和达标标准，学到时再定。前面学得快就合并，卡住就插过渡节。
- 不排日历。只说「一共大约几次学习」，不写「周三学什么」。
- 计划在对话里最多显示 15 行。完整的计划在文件里，用户想看再打开。

### 6.3 当前节的格式

```markdown
### 第 3 节：异步函数的执行顺序
- 前置：第 2 节
- 教法：诊断纠偏
- 选这个教法的原因：摸底第 2 题答对但说不出原因
- 达标标准：给 3 段代码，都能说对输出顺序并讲出原因
- 检验方式：费曼讲解 + 1 道新题
- 状态：进行中
- 步骤（每步 10-15 分钟）：
  1. 探测：1 道预测输出题
  2. 纠偏：针对答错的点
  3. 变体题 2 道
  4. 费曼检验
```

状态只有五种：`未开始` / `进行中` / `已掌握` / `需复习` / `跳过`。

### 6.4 给当前节选教法

按顺序检查，第一条命中的就用：

| # | 情况 | 教法 | 为什么 |
|---|---|---|---|
| 1 | 用户点名要某种教法 | 用户指定的那种 | 用户说了算 |
| 2 | 用户从没接触过这一节的内容（摸底判为「没学过」且依据是没见过、看不懂或不确定，或开讲前问下来没接触过），动手类和概念都算 | 示范例题 | 零基础时自己摸索、自己推都推不动，先看完整示范再逐步放手最有效 |
| 3 | 摸底判为「半懂」 | 诊断纠偏 | 已经有理解，只是有偏差，找出来修正比从头讲快 |
| 4 | 动手类内容：写代码、操作工具、做题 | 练习批改 | 只有做才能学会 |
| 5 | 核心概念、原理，用户接触过，并且后面很多节都依赖它 | 第一性原理 | 地基要从最基本的事实搭起，不能直接背结论；但用户手上得先有事实可推 |
| 6 | 其他（零散知识点、规则、用法） | 练习批改；跨课程记录显示示范例题对这个用户更有效时改用示范例题 | 默认用最省时间的；用户自己的记录比通用规则更准 |

第 6 条的「跨课程记录」：每种教法学满 3 节、首次检验通过率不低于 60% 才算数，只在练习批改和示范例题里挑（第一性原理和诊断纠偏有各自的适用条件），画像暂停时不给。

第 2 条排在最前面（用户点名除外）：上一节哪种教法好用、教练自己在收尾总结里写的「用户适合某种教法」，都不能盖过它（后者也不算用户点名）。摸底里没有这一节的内容时，开讲前先问用户接触过没有（完全没接触过 / 见过但没用过 / 用过），不要用内容题来探。

费曼法不参与这张表：**每一节的检验环节固定用费曼**，另外每学完一个阶段安排一次费曼大复盘，把这个阶段串起来讲。

### 6.5 让用户随时知道在做什么

光把计划写好还不够，学的过程中也要随时能看到位置：

- **每轮回复结尾带一行位置条**，格式固定：
  `📍 第 3 节「异步函数的执行顺序」· 第 2/4 步：纠偏 · 下一步：做 2 道变体题`
- **一节课的步骤同步进待办工具**，界面上能看到打勾进度。
- **用户问「我在干嘛」「学到哪了」**，用 3 行回答：终点是什么、现在在第几节第几步、这一步做完接下来做什么。
- **每步结束停一下**：一步做完先确认，再进下一步，不连着往下讲。
- **一次学习时间到了就收尾**：快到用户设定的时长时，不再开新步骤，先记录进度，告诉用户下次从哪继续。

### 6.6 交给用户确认

只给用户看路线层：终点考核、小节标题（每节一句话）、大约要学几次，以及第一节的步骤。用户可以改顺序、删节、指定教法。确认后写入计划，直接开始第一节。

## 7. F4 小节循环

每一节都走同样 5 步：

```
① 开场探测 ─► ② 按教法教学 ─► ③ 检验 ─► ④ 判定 ─► ⑤ 记录
     │                                    │
     └─ 已经会了 ─► 直接跳到 ③              └─ 未达标 ─► 换教法规则（§7.3）
```

1. **开场探测：** 不知道用户接触过没有，先问一句。从没接触过就直接开讲，不出探测题；接触过的再用一个问题探一下知道多少，答得很好就直接跳到检验，别讲用户已经会的东西。
2. **教学：** 加载这一节对应的教法 skill，按它的规则走（见 §8）。
3. **检验：** 按这一节的「检验方式」做。用的题不能是教学中讲过的原题。
4. **判定：** 对照「达标标准」，只有达标和未达标两种结果。
5. **记录：** 调用 `learn done` 记录结果；有错误理解就调用 `learn mistake`。

### 7.1 什么算达标

- 检验题做对，**而且**能说出为什么
- 费曼讲解里，追问 3 次以内没有暴露关键漏洞

两条都满足才算达标。

### 7.2 用户想跳过

用户说「这节我会了」：直接进检验。过了就标 `已掌握`；没过就告诉用户哪里没过，问要不要学这一节。用户坚持跳过：这一节不标掌握，先学后面不依赖它的节；依赖它的节要用户确认后才硬开始，终点考核前回来补检验。

### 7.3 卡住时换教法

**用户说「换种方式」：直接换，不问、不让挑。** 讲课时用户说「换种方式」「换个讲法」「换个学法」，或者说乱、烦、算了，意思是：这样讲没学懂，耐心也快没了。用户一般不会主动要求换，开口时已经卡了好一阵。这时不问「是这一步换个讲法还是整节换学法」，不给几种做法让用户挑，也不解释原来为什么那样讲。一句话认下没讲清，这一轮不出题，在原来那张表上取更小的一块（必要时用用户自己的代码），只完整示范卡住的那块（完整代码和真实输出；打比方用生活例子，讲完对回这张表），只问看懂没有（附一个「先到这，下次再说」）。

- 当前不是示范例题就换成示范例题，没做的步骤从示范重拆，这节剩下的都按它讲完，不再换回去；已经是示范例题就不换教法，同样从示范重拆，退回示范这一档（位置条跟着变）。
- 这是用户要求的换（`learn switch --user`），不算进下面的「一节最多换一次」；用户点名要某种教法的，也这样记，照点名的做。
- 正在检验时不再问下一项，记这次检验中途停下（`learn done --fail --stopped`：记为没过，但不算进「连续 2 次未达标」，免得同时冒出拆节、退回前置节的提示），再换。
- 重讲完还说没看懂，才把讲解按句编上号，问卡在第几句（用户回一个号就行）；同一块因为「换」重讲过还不通，按下面的「还卡」拆节或退回前置节，不再第三次换说法。
- 话里是想停的（「算了，今天不学了」「烦死了，先到这」），按累处理：问要不要停。不在讲课时（立目标、出计划）说烦，也不换教法。

为什么这样定：10-16 用户两次说换（「换一种教学方式呢」「换一种学法」），教练一次换成了接着出诊断题，一次给了三种做法让用户挑，补练步骤又混进了没选的那种；第二天用户说「好烦啊，一会这样一会那样」。用户事后说明：只有当前的方式没学明白、又耗光了耐心，才会开口要换。这时再提问、再让人选，耗的都是剩下的那点耐心。示范例题最省力（看完整示范，不用猜），所以固定换到它；换到它就停下，不会越换越乱。

同一个点连续 2 次没答对，先缩小：只讲错的那一步，在同一张表上取更小的一块。还不行才按这个顺序换：

| 当前教法 | 换成 | 再不行 |
|---|---|---|
| 示范例题 | 退一档放手程度（补全题 → 再看一遍示范）；同一块连续 2 次说没看懂，把讲解按句编号，问卡在第几句、哪个词 | 退回前置节 |
| 练习批改 | 诊断纠偏（找出错因） | 退回前置节 |
| 诊断纠偏 | 第一性原理（从头搭）；用户其实从没接触过就换示范例题 | 退回前置节 |
| 第一性原理 | 换一个例子或类比重讲一次 | 退回前置节 |

换教法时，没做完的步骤按新教法重拆（做完的保留），并加载新教法的 skill 从它的第 1 步做起。

**一节最多换一次（用户说换、点名的除外，脚本用 `--user` 另记）。** 换过一次还卡，多半不是教法不对，而是一节里东西太多、或者例子一直在变：只卡在一块就用 `learn split` 把它拆成单独一节（§10），本节只检验做对的部分。正在检验的时候不换教法：先把这次检验判完（没过就记未达标、追加补练步骤；用户说换的记中途停下 `--stopped`），再换，脚本在检验那一步拒绝换教法（同一种教法重拆步骤也拒绝）。换过一次后，脚本在 status、`learn done --fail` 和再次换教法时提醒「已经换过 N 次，不要再换」。

「退回前置节」的意思是：卡住的原因多半是前面某节其实没学会。出一道前置节的题测一下，没过就把那一节状态改成 `需复习`，先回去补；正在学的、依赖它的节先暂停，做过的步骤保留。

如果卡住的原因是本课以外的技能（学 Spring 却卡在 Java 语法上），不退前置节，按 §4.1 的「课中发现缺先修」处理。

每次换教法都在 `log.md` 记一笔，原因写清楚。

## 8. 五种教法的执行规则

每种教法是一个 skill，教学时按需加载。这里写每种的核心规则和结束条件。

**所有教法 skill 遵守同一套约定**，这样它们才能被总控随意切换：
- 开头：从进度文件读这一节的标题、达标标准、上次卡住的点，**不自己重新摸底**。
- 中间：一次只讲一个点，最多问一个问题；每步结束输出位置条（§6.5）。题目自成一块、放在回复最后：要用的代码、形状和前面的结论都写进题里，不说「上面那个」；要跑的代码先跑完再写正文，免得题目被中间的思考和运行结果隔开。用户常常学一会儿去干别的，回来只看最后一块就能接着答。
- 结尾：调用 `learn` 记录结果，再回复用户。
- 不自己决定下一节学什么，交回总控。

### 8.0 示范例题（worked-example）

**适合：** 用户从没接触过的内容（写第一个函数、第一次用 git、第一次见 numpy），动手类和概念都适用。

按「我做 → 一起做 → 你做」三步逐渐放手：

1. **完整示范：** 先用大白话说这东西干什么用，举一个生活里看得见的例子，再做一道最小的题：贴完整代码和真实输出，每一步都说出「为什么这么做」。一轮只讲一小块，新词先解释再用。讲了新东西的那一轮只问看懂没有，不出题（讲过的东西的新情况也算新东西）；看懂了出一道只改一两个数的同类题确认，没看懂就换一个更具体的例子重讲那一块。
2. **补全题：** 给一道同类题，只留关键的 1-2 步让用户补。要补的只能是示范里原样出现过的写法；示范里没有的形式先示范。补错在没示范过的地方，直接给正确写法，不让猜。
3. **独立题：** 换一道同类题（换场景和数字，形状和行列含义不变），用户从头到尾自己做。

**先写预测，再运行。** 每道题都让用户先写预测，考什么写什么（输出、形状或会不会报错），写完再跑代码对，不一样再问「哪一步和你写的不一样」（检验时只判对错，不追问）；能写出来的不出选择题、判断题。用户在 10-14～10-17 的记录里能背规则、能做判断题，却在自己写形状时出错：`@` 的三条规则一字不差背得出，`(5,3)@(3,2)` 却答成 `(3,3)`；`sum(axis=0)` 的值算对，形状写成 `(1,5)`。选项替他做了「自己写出来」那一步，练的和要会的对不上。自己写出来、马上看到对错，比再认记得牢（生成效应：Bertsch 等 2007，d=0.40；测试效应：Rowland 2014，g=0.50，回忆式测验比再认式收益大）。

**形状类的规则写成三行推导。** 示范时写：① 参与的数组各是什么形状；② 按这条规则比哪几位（广播从右往左逐位比，相等或有一边是 1；`@` 比左边最后一位和右边倒数第二位；axis 去掉那一位；reshape 比元素总数）；③ 结果形状，或哪一位对不上。用用户自己的说法。笔逐步交给用户：示范时教练写全 → 补全题从用户上次错的那一行起空 → 独立题三行全由用户写 → 下一道只写答案。偶尔问「把 3 改成 4，哪一行会变」，答不上说明只是照格式填，回到示范。这是示范例题逐步撤除（Renkl 等 2004；Barbieri 等 2023 元分析，示范例题对数学 g=0.48），撤的是推理步骤，不只是代码。

整节用同一张例子表；真要换形状，单独讲一轮，先说清换成了什么、跟刚才哪里不一样。

**结束：** 独立题做对。
**禁止：** 示范时只给代码不讲理由；示范完马上出题；让用户猜没讲过的写法；用户还没补对就跳到独立题。用户在没讲过的东西上猜错不记成错误理解：那是没讲清。

### 8.1 第一性原理（first-principles）

**适合：** 核心概念、原理，而且用户手上已经有可推的事实。用户从没接触过（没见过这个库、这种写法、这个词）就推不动，先换示范例题。

1. 先问用户对这个概念的现有理解，找出其中「默认成立但没想过为什么」的假设。
2. 列出这个概念依赖的最基本事实（用户已经会的、或可以直接验证的）。
3. 从这些事实出发，用提问引导用户一步步推出结论，每一步只问一个问题。
4. 推完之后让用户用一句话总结「这个东西为什么是这样的」。

**结束：** 用户自己说出了推导链。
**禁止：** 先给结论再解释。

### 8.2 诊断纠偏（adaptive-mentor）

**适合：** 半懂、有错误理解。

1. 出一道专门能暴露错误理解的题（预测输出、判断对错、找错误），只考用户见过的写法和词。
2. 用户答错时，先问「你是怎么想的」，拿到用户的推理过程。
3. 精确指出推理里错的那一步，只纠正这一步，别重讲整个概念。
4. 补上缺失的逻辑，出一道换了外观但考同一个点的题验证。

**结束：** 换外观的题答对了。
**每次纠正都要调用** `learn mistake` 记录：错误理解原话、正确理解、出错的那节。

### 8.3 练习批改（coach）

**适合：** 动手类内容、默认教法。

1. 用最短的说明讲清楚这一步要做什么（够用就行）。任务要用到用户没见过的写法，先给完整的最小示例和真实输出，看懂了再布置，不让用户猜写法。
2. 布置一个小任务，难度比用户当前水平高一点。一次只布置一个，批改完再给下一个；布置了就按原样做完，任务本身有问题就在原任务上改，不中途换一种做法。
3. 用户提交后批改：先真跑用户的代码再判，先说对的地方，再按重要程度列出问题，每个问题只给提示不给答案。
4. 用户改完再批改，直到通过。然后布置一个稍难的变体。

**结束：** 变体任务一次通过（或只有小问题）。
**角色（只留 4 种）：** 按内容选一种，在 log 里记下用了哪个：

| 角色 | 什么时候用 |
|---|---|
| 出题人 | 默认 |
| 代码评审 | 编程类，用户交了完整代码 |
| 面试官 | 用户目标是面试或考试 |
| 苏格拉底式提问者 | 用户总能做对但说不出原因 |

### 8.4 费曼（feynman）

**适合：** 每节检验、阶段复盘。

1. 让用户把这一节讲给「一个没学过的人」听，AI 扮演这个人。
2. 用户讲完后，AI 追问用户讲得含糊或跳过的地方，每次只问一个，最多问 3 次。
3. 追问到用户卡住的点，就是知识盲点。
4. 按下面的判分清单逐项判，给出结果。

**判分清单**（AI 扮演学生时很容易说「讲得很好」，所以必须逐项判，不给整体印象分）：

| 项 | 合格标准 |
|---|---|
| 关键概念 | 这一节的核心概念都提到了，并且用词准确 |
| 因果关系 | 说出了「为什么」，不只是「是什么」 |
| 例子 | 自己举了一个例子，并且例子是对的 |
| 追问 | 3 次追问都接住了 |
| 边界 | 能说出至少一个「什么情况下不成立 / 容易用错」 |

**检验只检验：** 新题就 1 道、只考一个点，一轮只问这一道；达标标准有几项就分几轮。新题用本节讲课时那套例子的形状和含义，只换数字。某一项答错或讲不清：不在检验里讲课，也不把同一道题原样再问，记下这项没过、下一轮问下一项；都问完再判，没过的记未达标、追加补练，回到教学去补。用户在检验中说换种方式、乱、烦：不再问下一项，记这次中途停下（不算进连续未达标），按 §7.3 回到教学。

**结束：** 5 项全部合格 → 达标；任何一项不合格 → 指出是哪一项，盲点用 `learn mistake` 记录，按 §7.3 处理；几项里只有一项没过，记完未达标再把它拆成新的一节（§10），本节只判做对的部分。判分结果原样写进 `learn done` 的备注。
**禁止：** 用户讲的时候插话纠正，等讲完再说；没逐项判就说「讲得很好」。

## 9. F5 续学（每次打开对话）

1. 回答任何问题前先运行 `learn status`，拿到上次学到哪、学得怎样、未解决的疑问。
2. 用两句话告诉用户：上次学到哪、今天的安排。
3. **上次留了没答完的题，先答它：** 收尾时 `learn pause --question -` 从标准输入记下原题（代码、形状、条件写全），开场把它原样贴出来，用户先答；记到下一次记录步骤、检验或错题为止。用户 12 次中途离开再回来，只有 2 次是真忘了；有 3 次是离开前没解决的那一步回来还卡着；最顺的两次都是回来只答一道题。回来先答题比先看总结接得快（Altmann & Trafton 2002 的目标激活模型：离开前留下的线索把目标拉回来；回来先提取，不要重读）。
4. **再复习：** 用 `learn due` 取出复习日期已到的错点，每个出一道新题：
   - 答对 → 下次复习间隔拉长（1 天 → 3 天 → 7 天 → 14 天 → 移出错题本）
   - 答错 → 间隔重置为 1 天，必要时把对应的节改为 `需复习`
   - 一次最多复习 5 个，剩下的顺延；没到期的不提前考
   - 教学中又犯了已有的错（包括已经移出错题本的），按答错处理、放回错题本，不另记一条
5. 复习完进入 F4，继续下一个 `进行中` 或 `未开始` 的节。

错题如果标了「来自 X 的习惯」（按旧技能的经验做错的），复习题专门出一道按 X 的习惯会做错的新题。这门课在等另一门先修课：那门结业时自动解除等待（先修那项记为已会）；没结业就按 §4.1 的三个出口问用户。

还没立目标或还没出计划的课：不走续学开场，接着做没做完的那一步。

隔了 14 天及以上没学：先做一次快速摸底，只测已掌握的节，测不过的标为 `需复习`。

## 10. F6 调整计划

出现以下情况时调整，调整后告诉用户改了什么、为什么：

| 情况 | 调整方式 |
|---|---|
| 检验没过，但只卡在本节的某一块（其余做对了）；这一节换过一次教法还卡；用户说这节太大了 | `learn split <节>`：卡住的那块拆成新的节，接在本节后面依次学（原来跟在本节后面的节改成等它学完）；本节改成只考留下的部分，剩下的步骤重新给（只讲、只考留下的部分；已经学完就只留一步检验）。拆出去的节带着原来那节拆之前没过的检验，学到时再细化。错题里属于拆出去那块的挪过去（`learn mistake <id> --to <节>`），等那节检验过一次再复习，免得开场复习先考到还没讲完的东西 |
| 讲课时用户说「换种方式 / 换个学法 / 换个讲法」，或说乱、烦、算了 | 不问换什么、不给选项：`learn switch <节> worked-example "用户说换" --user --steps '[…]'` 从示范重拆剩下的步骤（已经是示范例题也这样，退回示范），这一轮只讲卡住的那块（§7.3） |
| 用户点名要某种教法 | `learn switch <节> <点名的教法> "用户点名" --user --steps '[…]'`，只按点名的那种拆步骤，不把别的混进来 |
| 退回前置节后仍然卡住 | 在卡住的节前面插入一个更小的过渡节 |
| 连续 3 节开场探测都直接过了 | 用户比摸底时更强，合并后面几节或跳到更深的节 |
| 用户说目标变了 | 回到 F1 重新定终点；新用到的先修补问，新增的能力补摸底（按能力合并，不冲掉原来的），保留已掌握的节 |
| 期限快到但进度落后 | 列出可以砍掉的非关键节，让用户选砍哪些，写清楚砍掉会怎样 |
| 学到一半发现缺某个本课以外的技能 | 按 §4.1「课中发现缺先修」：先讲最小部分，再只问怎么补 |
| 展开下一个阶段 | 新阶段要用到新的先修技能时，先补问（新的一批，最多 4 道验证题）再排课 |

改路线的规矩：先看当前完整路线，在它上面改。已有的节不改编号，新节用没用过的编号，先后靠依赖表达；没写用到哪些先修的节沿用原来的；删掉学过的节要用户确认。新加的前置节还没学完时，正在学的节先暂停，做过的步骤保留。

## 11. F7 结业考核

所有节都 `已掌握` 后，做 F1 定下的终点考核。

- 考核内容必须是新的，不能复用教学和检验中的题。
- 通过 → 记为结业，给出一份总结：学了什么、哪些点曾经错过、建议的下一个学习目标。脚本把这门课的技能以「结业」证据记进画像；如果有别的课在等这门先修，自动解除那门的等待（先修那项记为已会，画像里给它记一条「会一点」的结业证据），并提示用户可以回去学了。
- 没通过 → 找出没通过的部分对应哪一节，标为 `需复习`，回到 F4。

## 12. 预设由哪些部分组成

| 部分 | 放什么 | 对应 DSH 插件 |
|---|---|---|
| 人设（总控） | 底线（§1）、总流程（§3）、开场规则、滚动细化与位置条（§6.2、§6.5）、教法选择规则（§6.4）、换教法规则（§7.3） | `dsh-persona` |
| 流程 skill | `learn-intake`（F1+先修+F2）、`learn-plan`（F3+F6）、`learn-review`（F5+F7）、`learn-profile`（查看和纠正画像） | `dsh-skill-filesystem` + `dsh-tool-skill` |
| 教法 skill | `teach-worked-example`、`teach-first-principles`、`teach-diagnose`、`teach-coach`、`teach-feynman` | 同上 |
| 读写档案和画像 | 进度、画像都只通过 `learn` 脚本读写 `~/.dsh/learning/` | `dsh-tool-fs`、`dsh-tool-fs-search` |
| 问用户 | 立目标、确认计划时给选项 | `dsh-tool-ask-user` |
| 跑代码 | 编程类技能的练习和检验 | `dsh-tool-bash` / `dsh-tool-pwsh` |
| 查资料 | 准备教学内容、核对事实 | `dsh-tool-web` |
| 长对话 | 防止上下文爆掉 | 压缩组（同 standard 预设） |

不挂：计划模式、子代理、workflow。学习是一对一对话，这些用不上，反而占提示词。

**和外部 skill 的关系：** first-principles-skill、adaptive-learning-mentor、Learning Coach、feynman-tutor 这四个外部 skill 不直接装，只吸收它们的机制，按 §8 开头的统一约定重写。adaptive-learning-mentor 拆成两半：摸底部分进 `learn-intake`，纠错部分进 `teach-diagnose`。Learning Coach 的 10 种角色精简成 `teach-coach` 的 4 种。全部重写，不复制原文，因此不受原 skill 许可证限制；如果以后要引用原文，先确认其许可证。

**放在人设里还是 skill 里：** 每一轮都要遵守的放人设（底线、路由、选教法和换教法的规则），只在某个阶段用到的放 skill。人设控制在 2500 字以内（现在约 2500 字）。

## 13. 学习者画像

跨课程记一份「用户会什么」，用在三处：先修问答少问、摸底起点更高、教学时拿用户会的技能打比方。

### 13.1 记什么

每个技能记一串证据，不直接存档位：

| 证据 | 来源 | 可信度 |
|---|---|---|
| 自述 | 先修问答里用户的选择，或用户明确纠正自己的水平 | 最低：只有自述时封顶「会一点」 |
| 题目验证 | 先修验证题、用户说自己会时出的验证题 | 中 |
| 先修节通过 | 先修节检验通过（只学了本课要用的部分，记「会一点」） | 中 |
| 结业 | 本预设里一门课结业考核通过 | 最高 |

档位由脚本按证据现算：验证类证据按时间顺序，往上可以直接升，往下一次只降一档；用户自己说得比验证结果低，按自述；最近一次验证超过 180 天标「久未验证」，拿来跳过提问之前先复核 1 题。

不记：姓名、单位、联系方式、学习风格偏好，以及没经用户回答的项目线索和模型推断。

### 13.2 什么时候写

只有四种时机，都由脚本自动写，并输出一行「画像：已记入 …（e12）。不对就说『删掉这条』」，模型原样转告：

1. 用户自己说的（先修问答的选择，或明确纠正）；
2. 验证题结果；
3. 先修节检验通过；
4. 结业。

### 13.3 怎么用：拿会的技能打比方

只用有验证证据的技能（status 的「可类比」行，最多 3 个）。开始一节正课时脚本给出固定格式（续学时 status 也会给，先修节不给），缺一行不算讲完：

```
〔用你会的 Java 打个比方〕
对应：本课的 X ≈ Java 的 Y
相同：1-3 点
不同：至少 1 点，附最小例子
别套用：什么情况下按 Java 的习惯会出错
```

讲完接本课的正式说法和一个最小例子（完整代码和真实输出），问用户看懂没有；看懂了再出 1 道针对「不同」、按旧习惯会做错的预测题，题里只用讲过的写法，答错再纠正，错题标上「来自 Java 的习惯」，复习时出一道按旧习惯会做错的新题。没有对应物的概念不硬凑，直说「这里别用 Java 的思路」。

依据：
- 教材里的类比大多缺「指出局限」这一步（Aksit & Budak）。
- 「看着一样、行为不同」是转语言时最常见的错误来源：迁移相关的发言里负迁移占 66.4%（Shrestha 等 2018）。Tshukudu 2022 把这类概念单独归为一类，并验证了对比纠错的做法。
- 按背景个性化的类比，测验提升并不比通用讲解高：通用讲解组提升 2.64 分，个性化组 2.56 分，个性化组只在投入感和自评上更好（Cao 等，ICCE 2024）。Google 的 Learn Your Way 整体比 PDF 阅读器有效（p = 0.03），但作者说分不清是哪项改动起的作用（LearnLM《Towards an AI-Augmented Textbook》）。

所以类比只当入口，检验标准不变。

### 13.4 用户怎么查看和改

- 「你记得我什么」：`learn profile` 原样列出，每条带 id、来源、日期。
- 说自己会得更少：直接采信；说自己会得更多：出 1 题，答对才升。先修问答进行中说的「会不会」，按先修问答记，不走这条。
- 删一条证据 / 删整个技能 / 暂停 / 清空，都是脚本命令，不靠模型手改文件。
- 画像文件默认不进学习档案的 git 历史；删掉的条目连备份一起删，清空就是真的清空（原来暂停的仍保持暂停）。用户连了同步仓库（多台电脑接着学）后，画像随进度一起进 git、推到用户自己的私有仓库，这时删掉的只是当前版本，仓库历史里还留着删之前的版本，脚本删除时会说明。画像和课程进度互不影响：清空画像不会改动课程进度。

## 14. 画像调研：开源项目怎么做

设计画像前调研了 48 条资料，能打开原文的都对照源码或全文核过：46 条核心结论成立（其中约 34 条改正了细节，下文用的是改正后的说法），2 条没通过（Tutor-GPT 一条、OATutor 一条）；少数论文只读到摘要，ChatGPT、Gemini 的记忆说明只能靠搜索摘要。下表只列开源项目，商业产品和论文单列在后面。

| 项目 | 怎么做画像 | 我们借了什么 | 没借什么 |
|---|---|---|---|
| [HKUDS/DeepTutor](https://github.com/HKUDS/DeepTutor)（`deeptutor/services/memory/`） | 三层本地文件记忆；画像条目用固定档位，必须带证据引用，禁用「精通」这类绝对化的词，由代码强制 | 固定档位 + 证据引用 + 禁用词，全部由脚本校验 | 要多次调用模型的整理管线（DSH 没有后台任务） |
| [memodb-io/memobase](https://github.com/memodb-io/memobase) | 固定的 topic / sub_topic 槽位；合并只有追加 / 更新 / 放弃三个动作 | 固定字段，每个字段写清更新规则 | 默认「推断隐含信息、允许自创字段」（会鼓励模型编） |
| [mem0ai/mem0](https://github.com/mem0ai/mem0) | 自由文本事实，存在向量库里；每条区分是用户说的还是助手说的 | 证据区分来源 | 向量库和自由文本 |
| [Letta / MemGPT](https://docs.letta.com/guides/agents/memory-blocks) | 记忆块带用途说明和字数上限 | 常驻只放一行摘要（status 的「可类比」），详情按需查 | 托管服务 |
| [plastic-labs/honcho](https://github.com/plastic-labs/honcho) | 用户卡片限条数、限单条长度，只准固定前缀，不合格拒绝 | 技能条数（50）、单条说明（120 字）、技能名（40 字）硬上限，超了拒绝；每个技能的证据超过 8 条时先丢最旧的自述，刚记入的和结业证据不丢 | 后台推理（dreaming） |
| [jbu/personis](https://github.com/jbu/personis) | 每项属性挂一串证据，读取时现算值；默认取最新一条 | 证据只追加、档位现算 | 「最新一条获胜」：一句随口的自述会盖掉题目验证 |
| [GeminiLight/gen-mentor](https://github.com/GeminiLight/gen-mentor) | 技能差距清单：技能名、要求程度、当前程度、理由 | 先修每项必须写「本课用它做什么」 | 让模型报进度百分比（它自己的评测里同一输入两次给出 20% 和 60%） |
| [weorbitant/orbitant-poc-skills](https://github.com/weorbitant/orbitant-poc-skills) | Claude Code 学习技能套件，本地 Markdown，选项式提问、一次一题 | 固定选项 + 一次一题 | 学习风格偏好字段 |
| [JushBJJ/Mr.-Ranedeer-AI-Tutor](https://github.com/JushBJJ/Mr.-Ranedeer-AI-Tutor) | 提示词里的学生配置（深度、学习风格等）；计划先列先修课 | 先修单独成段 | 不问会不会就无条件生成先修；按学习风格匹配教法（缺乏实证） |
| [metacademy](https://github.com/metacademy/metacademy-application) | 开源概念依赖图，每条依赖写明原因 | 先修带「为什么要它」 | 建完整知识图谱（单用户用不上） |
| [roadmap.sh](https://github.com/kamranahmedse/developer-roadmap/pull/8886) | 个性化路线图：裁掉的主题只标「跳过」，随时可以切回 | 跳过的先修保留可见、随时可改 | — |
| [specfy/stack-analyser](https://github.com/specfy/stack-analyser) | 从仓库清单文件识别技术栈，每条带命中依据 | `learn cues` 的「技术 ← 文件」格式 | 把识别结果当成用户技能 |
| [OATutor](https://github.com/CAHLR/OATutor)、[pyKT](https://github.com/pykt-team/pykt-toolkit) | 知识追踪概率模型 | 掌握档位由脚本按固定规则现算，不让模型判：自述最多算「会一点」、降档一次只降一档、超过 180 天未验证要复核 | 概率模型本身：单个用户每项技能只有一两道题，拟合不了 |

商业产品（读的是官方说明；ChatGPT 官方页面打不开，靠搜索摘要）：
- Claude 的记忆：可查看、逐条删除、暂停和清空分开，证件号、金融账号等永不保存。
- ChatGPT 的记忆：可查看、逐条删除、关闭，默认不主动记健康等敏感信息（用户明确要求时仍会记）。这两家的用户控制我们都借了。
- Khan Academy：最高档要在熟练之后再答对、答错逐档降。借了「一次只降一档」。
- GitHub Copilot Memory：每条记忆带出处，用之前先核实。借了「久未验证先复核」。
- Cursor：撤掉记忆管理界面后，用户只能回退版本才能删掉记忆。这是反面教材，所以删除都做成脚本命令。

论文和研究：
- 自评和实际表现的平均相关只有 .29（Zell & Krizan 2014），所以自述只当线索。
- 从 GitHub 活动判断「会不会」较准（精确率 77%-97%）；判断「多熟练」明显变差，而且因语言而异（56%-100%，PHP、Ruby、Shell、JavaScript、Java 不到 70%）（Disko，ICSE-NIER 2022 短论文），所以项目线索只用来提问。
- 按背景个性化的讲解，测验提升不比通用讲解高，只在投入感和自评上更好（Cao 等，ICCE 2024），所以类比只当入口。
- 可协商的学习者模型：学生申辩时由系统出快测决定（Bull & Al-Shanfari 2015），所以「说自己会」要出题。
- LLM 列先修技能可行，但常列出相关却不必要的技能（ESCO-PrereqSkill 基准），所以每项必须写用途。
